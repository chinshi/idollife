# T-041 落库补齐：四处只改内存的动作 + 结局抉择

> 来源：用户直派「修一下，然后发布」（2026-11-05）
> 状态：done

## 1. 问题

T-039 之后唯一的状态写入入口是 `pushFresh()`（先 `POST /v1/advance` 对齐，再 `PUT /v1/state` 落库）。
但还有几处动作直接调 `commitRun()` —— 只改 React 内存，**不经过服务端**：

| 动作 | 玩家看到的 | 刷新 / 换设备后 |
|---|---|---|
| 认识新朋友 `doMeet` | 扣了钱、加了人、写了日志 | 钱回来了、人没了 |
| 邀请入团 `doInvite` | 人进团了 | 人还在朋友圈、团里没他 |
| 请离成员 `doKick` | 人被踢了、进冷却 | 人还在团里 |
| 切换组合 `doSwitchParty` | 切到二团 | 回到一团（服务端存的还是旧 `activePartyId`） |
| 结局抉择 `decide` | 结局页出来了 | 回到游戏里继续玩 |

`decide` 更离谱：它发的是 `pushFresh((b) => b)`，请求出去了但一个字段都没改，等于纯空调。

## 2. 根因

`commitRun()` 现在的语义只是「同步内存 + 触发渲染」，落库由 `pushFresh()` 负责。
T-039-r4 把 20 处调用点改成 `pushFresh` 时漏了这 5 处；`commitRun` 名字看起来像"提交"，容易被误当成写入入口。

## 3. 改法

| 编号 | 改动 | 文件 |
|---|---|---|
| 1 | 请离逻辑从 App 内联搬到 core，成为纯函数 `kickMember(state, memberId)`（`ok` / `no-party` / `not-found`），返回新 state + 日志 | `core/friends.ts` |
| 2 | `RunState` 新增 `ending?: { decision, at } \| null`（老档缺省 = 还没抉择） | `core/types.ts` |
| 3 | `recordEnding(state, decision)` 幂等写入；`decidedEnding(state)` 用存档里的抉择重算结局文案 | `core/endings.ts` |
| 4 | `doMeet` / `doInvite` / `doKick` / `doSwitchParty` 全部改成 `runBusy(key, () => pushFresh(...))`，失败/不满足条件时返回原 base（不写库） | `App.tsx` |
| 5 | `decide` 改为 `pushFresh((b) => recordEnding(b, d))`，**回包后**才 `setEnding` + `setPhase('ended')`；写库失败提示重试、不进结局页 | `App.tsx` |
| 6 | 存档里有 `ending` → 刷新/换设备后自动回到结局页 | `App.tsx` |
| 7 | 结局页「再来一次」从「改内存 + 清本地档」改走 `doRestart()`（会新建云端档） | `Modals.tsx` |
| 8 | 上述按钮补加载态：`认知中…` / `邀请中…` / `请离中…` / `切换中…`；请离确认框回包后才关 | `FriendsPanel`、`PartyPanel`、`Modals` |

## 6. 没做的

- **结局入口还没接**：`phase === 'deciding'`（「两年了」三选一）在客户端从未被设置，
  所以 `decide` 目前仍是不可达路径。这次只修它的落库，是否按 `RUN_LENGTH_MS` 自动触发
  「两年抉择」需要产品口径确认后再做。
- `doRestart` 里 `commitRun(initialRun)` 用的是常量引用（未 `normalizeRun`），与别处重启路径不一致，
  但因为它随后会 `putState` 覆盖，暂未动。
