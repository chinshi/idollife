# T-043 体力显示恒为 0（stats 脏键）

> 来源：用户直派（2026-11-05 11:28）
> 原话：「是不是表现层没变？看图，刚完成一个爆睡行为，但是体力依旧显示 0」
> 状态：done

## 1. 真因：显示层读错了字段，体力根本没丢

直接读线上存档（`idollife_runs`，只读）：

```
run_id = run-mvz0cvih-1p3bl6
state.stamina = 100          ← 真实体力，满的
state.stats   = {"talk":57,"dance":45,"vocal":43,"acting":34,"stamina":null}
```

`attrValue()` 的旧实现：

```ts
const stats = state.stats as Record<string, number>;
if (key in stats) return stats[key] ?? 0;   // ← stats 里有 stamina 这个键，就优先用它
```

`stats.stamina` 是 `null` → `null ?? 0` → **0**。于是：

- 状态栏「体力 0」、属性 tab「体力 0」、进度条空 —— 三处读的都是 `attrValue(run,'stamina')`，所以**完全一致地错**
- 「爆睡没加体力」—— 加了（100 满），但显示恒为 0，看不出变化
- 「0 体力也能执行唱 K」—— 真实体力 100，`preflightAction` 合法放行，不是漏洞

三个现象同一个根因，是**纯表现层**，不是结算层。

## 2. 脏键哪来的：「学会休息」任务奖励

`tasks.json` 里：

```json
{ "id": "task-burnout", "rewards": { "stats": { "stamina": 25 } } }
```

`claimTaskReward()` 遍历 `rewards.stats` 的**所有键**直接写进 `stats`：

```ts
for (const [k, v] of Object.entries(rewards.stats ?? {})) {
  stats[key] = clamp(stats[key] + v);   // stats['stamina'] 是 undefined
}
```

`undefined + 25 = NaN` → 存进 JSON 变 `null` → 从此 `stats.stamina` 永久是 `null`，把真实体力盖死。
该任务是可重复的，所以这条脏键一旦产生就一直在。

顺手扫了三张表（`action_results` / `tasks` / `events`），只有 `task-burnout` 一条把资源写进 `stats`。

## 3. 改法：三重防线

| 层 | 改法 | 作用 |
|---|---|---|
| 读 | `attrValue` 只认 `STAT_KEYS`（vocal/dance/acting/talk），资源键走真实字段 | 脏键再也盖不住体力，**旧档无需迁移** |
| 写 | `task-burnout` 的 `rewards.stats.stamina` 经 `splitTaskRewards()` 提到资源位，真加到 `state.stamina`；`settle` / `events` 合并 `stats` 前过 `isStatKey` 白名单 | 不再产生新脏键 |
| 净 | `normalizeRun` 用 `sanitizeStats()` 只留四项能力；`applyServerState` 也走 `normalizeRun` | 读档即清洗，下一次提交把干净 stats 写回服务端 |

`preflightAction` / `settle` 的 `Number.isFinite` 兜底（T-042 加的）继续保留。

## 5. 守卫

- `packages/core/tests/stats-pollution.test.ts`（6 条）
  - `stats.stamina = null` 时 `attrValue` 返回真实 `run.stamina`（100 / 42）
  - `stats.mood = null` 同理
  - 四项能力照常读 `stats`；非法值归 0
  - `sanitizeStats` 只留四项，`'stamina' in cleaned === false`
  - 「学会休息」25 体力真到账（40 → 65），且 `stats` 里不出现 `stamina` 键
  - 奖励文案与实际发放一致
- `packages/client/tests/stats-display.test.ts`（3 条）
  - 用线上真实脏档跑 `normalizeRun`，`stats` 变干净、`attrValue` 回 100
  - 四项能力缺失/NaN 补 0
  - 干净档不受影响

- 还原 `attrValue` 的 `if (key in stats) return stats[key] ?? 0` → `expected 0 to be 100`
