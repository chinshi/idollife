## 需求描述

### 1) 导入链路

- `taskColumnField`（packages/core/src/task-headers.js）追加表头映射：`分类`→`category`、`组`→`guideGroup`、`自动领取`→`autoAccept`。
- `scripts/content-import.mjs` tasks 段读入这三个字段（按表头定位，与 deadlineDays 同一套做法；空 → 字段缺省）。
- `TaskDef` 增加 `category?: 'guide' | 'routine' | 'timed'`、`guideGroup?: string`、`autoAccept?: boolean`；导出 `TASK_CATEGORY_LABEL = { guide: '引导', routine: '常规', timed: '限时' }`。
- `check:data` 增加校验：category 缺省/非法值报错；guide 必须有 guideGroup 且不得同时带 deadlineDays；timed 必须有 deadlineDays。

### 2) core 任务系统（packages/core/src/tasks.ts）

- **自动领取**：新增 `autoAcceptTasks(state)`——把所有「autoAccept && taskStatus()==='claimable'」的任务依次走 acceptTask 路径（产生与手动领取一致的日志）。挂进结算流程（与 expireTasks 同时机调用，App 侧或 settle 侧均可，选一处并说明）。
- **引导组链**：guide 任务的可见性增加规则——`guideGroup` 为 G(n) 的任务，只有 G(n-1) 组内全部任务 `done`（taskExhausted 口径）后才可见；G1 常驻可见。实现进 `statusOf`（组未解锁 → `hidden`），并加环/跳号防御（G 编号不连续时按字典序也行，写明即可）。原 displayCondition 照常叠加。
- **timed 语义**：不需要新状态机——displayCondition（hasFlag 事件）+ autoAccept + deadlineDays 组合即可。但 `expireTasks` 的超时日志文案区分：「限时委托「xx」超时未完成。」
- 便捷查询：`briefTasks(state)` 给简报用——返回按分类分组、含 `status`、`progress`（复用 taskProgress）、`deadline`（复用 taskDeadline）的任务列表，排序：引导组号 → priority。

### 3) 客户端：右上角任务简报改版（App.tsx `.bar-right`）

- **分类显示**：三段式——引导（强引导样式）/ 常规 / 限时，段间有分隔或小标题。空段不渲染。
- **引导任务强引导样式**：主题金色系（与终阶阶段色 #d4af37 呼应），左侧竖条 + 加粗 + 微光背景，让玩家一眼知道「现在该干什么」。
- **限时任务**：橙红警示色 + 行尾倒计时（`taskDeadline().remainingDays` →「剩 N 天」，urgent 时 `remainingSlots` →「剩 N 次」并加红）。
- **任务文本 = 任务名（当前/目标）**：如「高朋满座（10/50）」——用 `taskProgress()` 的 current/target；推导不出进度的回退 `brief` 文案。**用任务 `name` 为主，进度取 completeCondition 推导**。
- **完成未领奖 → 打钩符号**：`completable` 状态的任务，行首圆点替换为 ✓（绿色/金色），**排在各自分区最顶**，点击该行跳转任务面板（setMainTab('task')）。
- 简报容量：最多显示引导当前组全部 + 常规 active + 限时 active/completable，超出折叠「+N」；空态保留「暂无进行中的任务」。
- TaskPanel（任务面板）同步按三分类分节，沿用简报的视觉语言（引导高亮、限时带倒计时、completable 打钩）。
