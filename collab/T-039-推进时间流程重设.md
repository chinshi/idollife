## 1. 目标

产品所有者拍板三条：

1. **离线挂机是核心玩法** —— 关掉页面时间照走，回来一次补齐。
2. **时间由本地发起，服务端校验；校验通过后服务端算收益，下发结果给客户端。**
3. **取消倍速，恒 1×** —— 一个行动 10 游戏分钟，节奏只由 `balance.timeScale` 决定（测试态 20 → 30 秒/条；生产态 1 → 10 分钟/条）。

因此本次重构的唯一目标：**把「两个引擎各自结算并互相覆盖」改成「客户端只报时刻、服务端唯一结算并下发」**，同时保留：

1. 离线挂机（关页面时间照走）
2. 随时停止
3. 行程编辑立即落盘，刷新/换设备不丢
4. **运行中改状态不打断玩家**
5. 任何分支都有可见反馈

> **不再保留**：倍速（1×/2×/4×/8×）、多设备接管按钮、只读横幅。

## 2. 根因（全部要消掉）

| # | 根因 | 位置 |
|---|---|---|
| R1 | **两个引擎都在写 `run.at`**：客户端 rAF 每 100ms `settle` 并上报；服务端每次读档也 `catchUp → settle` 并落库 | `App.tsx` tick、`server/src/clock-service.ts:41` |
| R2 | 双引擎只能靠逐字段比对合并，衍生 `mismatch`/`stale`/`too_fast`/`gapHeal`/`lost_pause`/`maxSteps` 续算 | `server/src/app.ts` sync 分支、`core/src/clock.ts` |

## 3. 契约

### 3.1 数据

```
RunRecord = { userId, runId, revision, seed, run, schedule, clock, updatedAt }

clock = {
  status: 'running' | 'paused',
  gameAt: number,      // 已结算到的游戏时间；不变量 === run.at
  wallAnchor: number   // gameAt 对应的服务端墙钟（ms）；paused 时保留但不参与计算
}
```

- **删除 `speed`**（v4 取消倍速）：时钟恒 1×，节奏只由 `TIME_SCALE` 决定
- **删除 `sessionId`、`ownerTs`**；`ownerId`（账号隔离）保留
- **删除 `idle` 状态**，只剩 `running` / `paused`
- 旧档 `sessionId` / `localClock` / `speed` 读时忽略，不迁移

> `gameAdvance(elapsedMs, speed, timeScale)` 的 `speed` 参数**保留**（core 的 D-017 唯一换算公式，多处测试在用），但**时钟层固定传 1**。`ClockState` 里不再有 `speed` 字段。

#### 权威归属（**不要读成「服务端不存时间」**）

服务端是唯一存档方、唯一时间来源。客户端**不存** `wallAnchor` / `gameAt`，也不推进它们：

| 内容 | 权威位置 |
|---|---|
| 行程（`schedule`，含每条 `startAt` / `endAt` / `done`） | 服务端 `RunRecord.schedule` |
| 游戏状态（`run`：钱 / 体力 / 粉丝 / 属性 / flags / log） | 服务端 `RunRecord.run` |
| 挂机起点 `wallAnchor` + 已结算游戏时刻 `gameAt` | 服务端 `RunRecord.clock` |
| 当前时间 | 服务端墙钟；客户端只算 `serverTime − Date.now()` 偏移 |
| 当前存档版本 | `revision`（服务端自增，客户端只回传） |

**换设备 / 刷新 / 断网回来都走同一条路**：`GET /v1/state` 取回 `run + schedule + clock + revision` → 本地按 `gameAt + (serverNow − wallAnchor) × TIME_SCALE` 画进度条 → `POST /v1/advance { targetAt: null }` 补齐。**不需要旧设备在场，也不需要交接**，`sessionId` / 接管 / 只读那套整个删掉。

`targetAt` 的唯一用途是**声明「我在这个停点要结果」**（一般是下一条行动的 `endAt`，便于逐条回放），它不能改变服务端认为的当前时间：报 `null` → 补到上界；报 `≤ 上界` → 结算到该点；报 `> 上界` → 裁到上界。

**两层安全各管一件事**：内容正确性靠「客户端不上报 state，服务端重放」（上界管不了内容）；时长正确性靠上界（内容校验管不了时长）。**不许**为了"省一次往返"让客户端上报结算结果。


### 3.2 上界公式（唯一安全边界，必须抽成纯函数并单测）

```ts
// core 新增
export const CLAMP_TOLERANCE_MS = 500;

export function maxTargetAt(clock: ClockState, serverNow: number, timeScale = TIME_SCALE): number {
  if (clock.status !== 'running') return clock.gameAt;
  return clock.gameAt + gameAdvance(serverNow - clock.wallAnchor, 1, timeScale) + CLAMP_TOLERANCE_MS;
}
```

`wallAnchor` 前移（**不是重置**）：

```ts
export function advanceAnchor(clock: ClockState, newGameAt: number, timeScale = TIME_SCALE): number {
  if (clock.status !== 'running') return clock.wallAnchor;
  return clock.wallAnchor + (newGameAt - clock.gameAt) / Math.max(1, timeScale);
}
```

### 3.3 端点（只留四个）

#### `POST /v1/advance` —— 唯一推进入口

body：`{ expectedRevision, targetAt?: number | null }`

1. auth 失败 → 401；`runId` 缺失 → 400
2. 记录不存在 → 404 `not_found`（新档先走 `PUT`）
3. `rec.userId !== user.id` → 403
4. `expectedRevision !== rec.revision` → 409 `conflict`（回包带当前权威状态）
5. `targetAt` 为空 → `targetAt = maxTargetAt(clock, now)`
6. `clampedTarget = Math.min(targetAt, maxTargetAt(clock, now))`；`clamped = targetAt > maxTargetAt`
7. `clampedTarget <= clock.gameAt` → 不结算，直接返回 `executed: []`（幂等）
8. `settle(run, schedule, clock.gameAt, clampedTarget, seed, { endAt: RUN_END_AT, maxSteps: 2000 })`
9. 按 §6 推导新 `status` / `wallAnchor`
10. 有推进或状态变化才 `putRun`（`revision + 1`）
11. 返回：

```
{ run, schedule, revision, seed,
  clock: { status, gameAt, wallAnchor },
  executed: string[],     // 最近 60 条
  stepped: number,        // 本次实际结算条数
  stoppedReason,
  nextStopAt, clamped, clampedTo,
  serverTime }
```

> 不允许在这里做「服务端自取 now」的兜底推进。没有 `targetAt` 时用上界，这是唯一允许的默认值。

#### `GET /v1/state` —— 纯读

1. auth / 归属 / 404 / 403 同上
2. **不调用 `settle`、不 `putRun`**
3. 返回 `{ run, schedule, revision, seed, clock, nextStopAt, serverTime }`

#### `PUT /v1/state` —— 状态变更

body：`{ expectedRevision, run?, schedule? }`

1. auth / 400
2. 记录不存在 → **创建**（`revision: 0` → 落 1；`clock: { status:'paused', gameAt: run.at, wallAnchor: 0 }`），跳到第 7 步
3. `rec.userId !== user.id` → 403
4. `expectedRevision !== rec.revision` → 409 `conflict`
5. **`run.at !== rec.run.at` → 409 `stale_clock`**（客户端必须先 `advance`）
6. schema 校验：`run.at` / `run.stamina` / `run.stats.vocal` 为 number，`run.log` / `schedule` 为数组 → 400
7. 落库 `revision + 1`，返回完整状态

> `PUT` 不做任何结算。它只处理「同一游戏时刻的状态变更」。

#### `POST /v1/start`

body：`{}`（**无参数**，不再接受 `speed`）

1. auth / 归属
2. 无未完成排程 → 409 `no_schedule`
3. `run.pendingEvent` 非空 → 409 `pending_event`
4. **已 running → 幂等返回**（v4 起没有「改速」这个动作）
5. paused → 落 `{ status:'running', gameAt: run.at, wallAnchor: now }`，`revision + 1`
6. 返回状态

#### `POST /v1/pause`

body：`{ targetAt?: number | null }`

1. auth / 归属
2. running → 按 §3.3 advance 第 5~9 步结算到 `min(targetAt ?? 上界, 上界)`，再置 `status='paused'`
3. paused → 幂等返回
4. 返回状态

#### 删除

`/v1/sync`、`/v1/clock/start`、`/v1/clock/pause`、`/v1/clock/session`、`/v1/clock/event`、`/v1/clock/takeover`、`sameSnapshot`、`allowedGameAt`、`gapHeal`、`lost_pause`、`taken_over`、`loadAndCatchUp`、`saveClock`、`sessionId` 全部分支，以及 **`ALLOWED_SPEEDS` / `bad_speed` / `speed` 校验**。

### 3.4 core 新增纯函数

```ts
/** 下一条未完成项结束的游戏时间；无则 null（与 status 无关，paused 也返回，供 UI 显示） */
export function nextStopAt(run: RunState, schedule: ScheduleItem[]): number | null;
```

- 取未完成项中 `startAt` 最小的一条 → `endAt ?? startAt + ACTION_MS`
- 不做资源预判（资源不足由下一次 `advance` 的 `stoppedReason` 带回）

`catchUp` 保留但改为薄包装：`catchUp(run, schedule, clock, nowWall, seed, opts)` = `advanceTo(run, schedule, clock, maxTargetAt(clock, nowWall), seed, opts)`，只给测试与后台脚本用，**服务端路由不得调用**。

### 3.5 客户端

#### 3.5.1 渲染（不结算）

```

          ? clock.gameAt + (serverNow − clock.wallAnchor) * TIME_SCALE
```

## 4. 停点判定表（验收逐条对）

| 场景 | 期望 |
|---|---|
| 排程 3 条、资源足、无事件 | 全部走完，`'exhausted'`，`status='paused'` |
| 第 2 条带 `stopAfter` | 停在它结束，`'stopped'` |
| 下一条体力不足 | `gameAt` 停在**上一条结束**处（不前进到它开始），`'stamina'` |
| 触发重点事件 | 停在事件处，`'event'`，`pendingEvent` 非空，`paused` |
| 中间空档（某天只排 1 条） | 空档被跨过，无「对齐」副作用 |
| 离线 8 小时 | `advance { targetAt: null }` 补算完成，`gameAt` 前进量 ≈ 墙钟 × `timeScale`；**排程走完即停**（生产态排 7 天约 3.5 小时走完，这是产品口径，见 docs/30 §9.1） |
| `targetAt` 超上界 | 裁剪结算，`clamped: true`，客户端整份覆盖 + 提示 |
| `targetAt ≤ gameAt` | 幂等，`executed: []` |
| 排程走完再 `start` | 409 `no_schedule` |
| 已 running 再 `start` | 幂等，`revision` 不变 |
