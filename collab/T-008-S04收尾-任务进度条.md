## 一句话目标

任务面板里的「完成条件」从纯文字变成**可量化进度**：`舞蹈 18/30` + 进度条。复合条件优雅降级为纯文字。

## 需求描述

### 1. 抽取值函数（关键：不许写第二套）

`expr.ts` 里构造表达式变量表（`data` 对象：`stamina` / `money` / `mood` / `stats` / `axes` / `fans.*` / 分组属性…）的那段逻辑，抽成一个**可复用导出函数**，例如：

```ts
export function buildExprData(state: RunState): Record<string, unknown>
```

要求：
- `compileExpression` 内部改用它（行为不得变化，现有 84 条测试原样通过）
- 进度计算也用它，**不得另写一套取值逻辑**（否则 mood 缺省 70 这类规则会漂移）

### 2. 进度解析（`packages/core/src/task-progress.ts` 新建）

输入 `completeCondition`（表达式字符串），输出：

```ts
export interface TaskProgress {
  label: string;    // 中文显示名，如「舞蹈」「舞台粉」
  current: number;  // 当前值
  target: number;   // 目标值
}
export function taskProgress(state: RunState, task: TaskDef): TaskProgress | null
```

规则：

| 条件形态 | 行为 |
| --- | --- |
| `<变量> >= <数字>` | 提供进度，`target = 数字` |
| `<变量> > <数字>` | 提供进度，`target = 数字 + 1`（要严格大于，最小可达值） |
| 复合（含 `and` / `or` / 函数 / 两个以上比较） | 返回 `null`（降级为纯文字，**不要瞎猜**） |
| 空条件 / 无 `completeCondition` | `null` |
| 变量取不到值 | `null`（不要显示 0/x 骗人） |

`label` 取值优先级：① `attributes.json` 里该变量的中文名 → ② 中文别名表反查 → ③ 变量原名。`fans.stage` 这类显示为「舞台粉」等（attributes.json 或既有 `FAN_TYPE` 标签有则用，没有就显示 `舞台粉(n)` 风格，别硬编码一套新的）。

### 3. 界面（`packages/client/src/components/TaskPanel.tsx`）

- 有进度：显示 `label current/target` + 一条进度条；`current` 超过 `target` 时按 100% 显示（不要超出条宽）
- 无进度：维持现状（纯文字条件）
- 已完成的任务不显示进度条（或显示满格，二选一，回执里说明选了哪个及理由）

样式尽量复用 `styles.css` 既有类，新增类名以 `task-progress` 前缀，别改动全局样式。

## 回执区（dsh 填写）

- 实现说明：

  1. **取值函数（关键：不写第二套）**
     - `packages/core/src/expr.ts` 里原来的内部函数 `toData()` 抽成**导出**的 `buildExprData(state: RunState): Record<string, unknown>`，`compileExpression` 内部改用它。行为零变化：原有测试一条未改、全绿（现有 85 条口径见未决问题 1）。
     - `task-progress.ts` 的当前值**只从 `buildExprData()` 取**，没有另写一套取值；所以 `mood`/`satiety` 缺省 70、三轴/分组属性/粉丝等规则与条件求值完全同源（P7 用缺省 70 钉死）。
  2. **进度解析（`packages/core/src/task-progress.ts` 新建）**
     - `taskProgress(state, task): TaskProgress | null`，`TaskProgress = { label, current, target }`。
     - 形态只认两种：`<变量> >= <数字>`（target=数字）、`<变量> > <数字>`（target=数字+1）。
     - 其余一律 `null`：复合（and/or/多个比较）、函数、`hasFlag(...)`、比较号右边不是数字（如 `vocal >= dance`）、`<=`/`==` 等、空条件、缺 `completeCondition`、旧 JSON 对象条件、变量取不到数值。
     - 解析前用 **`expr-rules.js` 的 `normalizeExpr`**（与编译器同源），所以表里写中文别名/裸字段（`演唱 >= 100`、`ambitious >= 3`）也能正确折算成取值键；不是另起一套解析白名单（见未决问题 3）。
     - `label` 优先级：① `attributes.json` 中文名（含分组前缀形式：`trait.ambitious → 好强`、`fans.stage → 舞台粉`）② 中文别名反查（`total → 总属性`、`friends → 粉丝数`）③ 变量原名。
     - **`target <= 0` 直接返回 `null`**（策划裁定 2026-11-02）：`vocal >= 0` 这类条件玩家一步没做也会满格，属假达标，不提供进度、降级纯文字；`vocal > -1`（target=0）同理。P8 钉死。
  3. **界面（`TaskPanel.tsx`）**

     - 无进度：维持 `describeCondition(...)` 纯文字，与现状一致。
     - **已完成任务不显示进度条**（选了「不显示」：已完成任务在「已完成」页签里，进度无意义；显示满格会让「已完成」看起来像「刚好达标」）。若想要满格显示，改一行即可。
     - 样式新增 `.task-progress` / `.task-progress > span`（`task-progress` 前缀，沿用 `--accent`/浅灰），未改全局样式。
