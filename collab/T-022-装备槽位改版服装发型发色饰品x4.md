## 1. 目标

装备槽位从「发型 / 服装 / 鞋袜 / 饰品」四槽，改为 **服装 1 + 发型 1 + 发色 1 + 饰品 4**，共 7 个槽位。

- 删除鞋袜槽（11 件内容已从 `content/all.xlsx` 移除）
- 新增发色槽（12 件内容已由策划落地：自然黑 / 亚麻棕 / 蜂蜜茶 / 深栗色 / 奶奶灰 / 雾霾蓝 / 薰衣草紫 / 樱花粉 / 薄荷绿 / 玫瑰金 / 白金 / 渐变挑染）
- 饰品由 1 槽变 4 槽，4 槽**通用**（不按部位细分，任意饰品可放入任意饰品槽）

## 2. 数据口径（策划已落地，不要改 xlsx）

`packages/core/data/equipments.json` 现有 68 件：

| 定义 slot（类别） | 数量 | 说明 |
|---|---|---|
| `outfit` | 30 | 服装，占 1 槽 |
| `hair` | 12 | 发型，占 1 槽 |
| `haircolor` | 12 | 发色，占 1 槽（新增） |
| `accessory` | 14 | 饰品，类别；可放入 4 个饰品槽中的任意一个 |

注意区分两组概念：

- **装备定义 slot**（`EquipSlotCategory`）= `outfit` / `hair` / `haircolor` / `accessory`，来自配置表，只有这 4 个值
- **角色身上的槽位**（`EquipSlot`）= `outfit` / `hair` / `haircolor` / `accessory1` / `accessory2` / `accessory3` / `accessory4`，共 7 个

## 3. 实现要求

### 3.1 类型（`packages/core/src/types.ts`）

```ts
export type EquipSlot =
  | 'outfit' | 'hair' | 'haircolor'
  | 'accessory1' | 'accessory2' | 'accessory3' | 'accessory4';

export type EquipCategory = 'outfit' | 'hair' | 'haircolor' | 'accessory';

equipped: {
  outfit?: string; hair?: string; haircolor?: string;
  accessory1?: string; accessory2?: string; accessory3?: string; accessory4?: string;
}
```

配置表里的 `slot` 字段语义是 **category**，建议在导入类型上改名或加 `category` 别名，避免与槽位枚举混淆（你自行决定，保持一致性即可，回执说明）。

### 3.2 槽位标签（`packages/core/src/items.ts`）

`EQUIP_SLOT_LABEL` 更新为：

| key | 文案 |
|---|---|
| `outfit` | 服装 |
| `hair` | 发型 |
| `haircolor` | **发色** |
| `accessory1` | 饰品一 |
| `accessory2` | 饰品二 |
| `accessory3` | 饰品三 |
| `accessory4` | 饰品四 |
| `accessory`（类别兜底） | 饰品 |

删掉 `shoes` 相关标签与常量。

### 3.3 装备 / 卸下逻辑

- `equipItem(state, invId, targetSlot?)`：
  - `outfit` / `hair` / `haircolor` 类装备：目标槽就是它的 category，同槽换装自动卸下旧的（沿用 T-019 既有逻辑，含 axes/stats 还原）
  - `accessory` 类装备：
    - 传了 `targetSlot`（`accessory1..4`）→ 装到该槽
    - 未传 → 填第一个空槽；四个全满 → 替换 `accessory1`（或按你的判断返回明确 notice，回执说明）
  - **同一件饰品不能同时出现在两个槽**：若该 invId 已装备在其他槽，先从原槽卸下
- `unequipItem(state, slot)`：按槽卸下，7 槽通用
- 饰品槽允许放不同饰品，也允许 4 槽放满；加成叠加照旧计算

### 3.4 旧档迁移（重要）

存档里可能有 `equipped.shoes`。因为装备加成是**直写 axes/stats**（T-019 未决 3 的方案），直接丢弃字段会让那部分加成永久留在角色身上。

迁移规则（读档 / normalizeRun 时一次性执行）：

1. `equipped.accessory` → 迁到 `equipped.accessory1`
2. `equipped.shoes` → 按下表**还原加成**（减掉对应值）后删除字段：

```ts
// 仅供旧档迁移使用的一次性数据（鞋袜槽 2026-11-03 移除）
const SHOE_LEGACY_EFFECTS: Record<string, { bonus?: Record<string, number>; hidden?: Record<string, number> }> = {
  'eq-canvas-shoes':    { bonus: { dance: 2 } },
  'eq-knee-socks':      { bonus: { talk: 1 } },
  'eq-black-over-knee': { bonus: { dance: 1, talk: 1 } },
  'eq-stage-socks':     { bonus: { dance: 1 } },
  'eq-martin-boots':    { bonus: { dance: 3 } },
  'eq-mary-jane':       { bonus: { acting: 2 } },
  'eq-platform-shoes':  { bonus: { talk: 2 } },
  'eq-ballet-flats':    { bonus: { dance: 2, vocal: 1 } },
  'eq-fishnet':         { bonus: { dance: 1, acting: 2 }, hidden: { others: 2 } },
  'eq-strapped-boots':  { bonus: { dance: 4 }, hidden: { self: 2 } },
  'eq-custom-boots':    { bonus: { dance: 5, vocal: 2 }, hidden: { fit: 3 } },
};
```

3. `equipped.shoes` 的值若不在上表内（legacy 自定义条目），无法还原 → 静默丢弃，在回执里说明残留影响（可忽略量级）
4. 旧档 `equipped` 里其它未知键一律丢弃

**注意**：迁移必须幂等（跑两次结果一致）。

## 5. 回执区（dsh 填写）

### 实现说明

1. **类型口径**
   - `types.ts`：`EquipSlot` 扩为 7 槽（outfit/hair/haircolor/accessory1..4）；新增 `EquipCategory = 'outfit'|'hair'|'haircolor'|'accessory'`；`equipped` 改为 7 个通道。
   - 配置表字段：`EquipDef.slot` 的类型改为 `EquipCategory`（字段名沿用表头 `slot`，语义=类别；数据不用改）。这样「类别」与「角色槽位」在类型层区分开，`slotsForCategory()` 负责映射（饰品→4 槽）。
   - `equipped` 里额外保留了一个 `@deprecated accessory?: string`：仅作旧档迁移中转（normalize 后一定不存在），保留的原因是策划已更新的 `items.test.ts` 用 `equipped[equipWithReq.slot]` 索引时 `slot` 是 category，类型上需要这个键才能编译（见未决 1）。
2. **`items.ts`**
   - `EQUIP_SLOT_LABEL` 更新为 8 键：服装/发型/发色/饰品一~四 + `accessory`（类别兜底「饰品」）；删除 `shoes`。
   - 新增 `EQUIP_SLOTS`（7 槽）、`ACCESSORY_SLOTS`（4 饰品槽）、`slotsForCategory()`、`equippedSlotOf()`。
   - `equipItem(state, invId, targetSlot?)`：
     - outfit/hair/haircolor → 固定各自槽；同槽换装先卸旧（含 axes 还原）。
     - accessory → 传 `accessory1..4` 就装该槽；不传则填**第一个空槽**；四槽全满时**替换 accessory1**。
     - 同一件装备不会占两个槽：若已装备在别的槽，先从原槽卸下（含还原）。
   - `unequipItem(state, slot)`：7 槽通用；兼容传入类别（`accessory` 自动挑第一个已装备的饰品槽，供旧调用/测试）。
   - `effectiveStats` 改为遍历 7 槽；旧 legacy 装备仍走 `legacy.affix` 兜底。
   - 删除所有 `shoes` 常量/遍历；`equipDefOf/entryTypeLabel` 等按 category 显示。
3. **旧档迁移（`save.ts`）**
   - 新增一次性映射 `SHOE_LEGACY_EFFECTS`（11 双鞋，bonus/hidden 按卡面表格）。
   - `migrateEquipped(run)`：`accessory`→`accessory1`（已有 accessory1 时保留后者）；`shoes` 按映射把显性加成从 `stats`、隐形加成从 `axes/negatives` **减回**（clamp 0–100），然后删除字段；未知鞋子 id 静默丢弃；其余未知键一律丢弃，只保留 7 槽。
   - 迁移放在 `normalizeRun` 里、**阶段推导之前**执行（还原鞋子可能改 `stats.dance`，会影响 `total`/阶段）；幂等（迁移后 shoes/accessory 键不存在，再跑无变化）。
4. **客户端 UI（`BagGrid.tsx` 装备区）**
   - 「背包 · 装备」页签顶部新增 7 格：上排 服装 / 发型 / 发色（3 等分、稍大），下排 饰品一~四（4 等分、稍小）；每格左上角标槽位名。
   - 已装备格：名称 + 稀有度边框色，点击**卸下**（hover 仍出 T-019 同款 tooltip）。
   - 空槽：虚线框 + 槽位名 + 「+」；点击展开「该槽可选装备」列表（饰品 4 槽都列 `accessory` 类），点条目即装备到该槽。
   - 背包格子仍保留已装备条目并打「E」（T-019 口径不变）；tooltip 直接复用现有 portal+fixed 三段式，没有新样式体系（只加了装备区的格子样式）。
5. **API**：`api.ts` 的 `doEquipBag(invId, targetSlot?)`、`doUnequipBag(EquipSlot)`；`App.tsx` 对应改签名并透传 `equipItem(..., targetSlot)`。
6. **其它**：`scripts/validate-data.mjs` 按说明未动（白名单已是 4 类别）；全仓 grep 只有 `save.ts` 的迁移映射/注释里还出现 `shoes`（预期保留）。
