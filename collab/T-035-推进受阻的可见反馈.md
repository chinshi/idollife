## 1. 问题（产品所有者实测反馈）

> 「开始推进按钮没办法点击了」→「属性验证没通过，但是没有反馈，因此阻止了推进开始」

按钮没坏，是 `advance()` 里的 preflight 拦住了，**并且把所有能看见的反馈都抵消掉了**。

### 1.1 实测根因（四层，全部要修）

| # | 位置 | 现状 | 后果 |
|---|---|---|---|
| 1 | `App.tsx` `advance()` | 命中 preflight 后执行 `setLastStop('')` | `TimeAxis` 的徽章条件是 `!running && lastStop && stopText[lastStop]`，空串直接不渲染 —— **主动抹掉了唯一在视线内的反馈位** |
| 2 | `LogPanel.tsx:71` | 完整句子只进 `notice`，渲染在右列「日志」模块**最底部一行小字** | 点击位置在顶栏中列，玩家视线根本不在右列底部；等于没提示 |
| 3 | `App.tsx` `STOP_TEXT` | 没有 `times` 键 | 即使把 reason 写进 lastStop，次数用尽也不显示徽章 |
| 4 | `PlanPanel.tsx:172` | `.plan-blocked` 常驻红字只在「行程」tab 内 | 玩家在**演出 / 商店 / 组合**页点推进时（顶栏是全局的）完全看不到 |

### 1.2 顺带查出的两个隐患（必须一起修，否则将来变死锁）

- **「下一条」两处各算一遍**：`App.tsx:788` 的 `pending` 是 `schedule.filter(!done)` **未排序**；
  `advance()` 与 `PlanPanel` 里是 `filter(!done).sort(startAt)`。现在靠「所有写入口都排序」侥幸一致，
  一旦某处 push 不排序，就会出现「PlanPanel 说能跑、advance 却被另一条拦住」→ 又是零反馈。
- **演出项没排除预检**：`settle.ts` 里 `item.kind === 'show'` 在 preflight **之前** `continue`，但 `advance()`
  的入口预检没做同样判断。现在恰好因为 `previewAction('show:xxx')` 返回 null 才没出事；
  将来 `previewAction` 对未知 actionId 兜底出非 null，就会把**不可删的演出项**卡住 → 玩家永久推不动。

## 3. 契约

### 3.1 「下一条」唯一口径

抽一个函数（建议 `packages/core/src/plan.ts`）：

```ts
/** 排程里下一条要执行的（未完成 + 按 startAt 升序第一条）；没有则 null */
export function nextPendingItem(schedule: ScheduleItem[]): ScheduleItem | null
```

- `App.tsx` 的 `pending` 派生、`advance()` 的 first、`PlanPanel` 的 `nextPending` **全部改用它**（或其排序结果），
  禁止任何地方再手写 `filter(...).sort(...)` 取第一条。
- `pending`（列表，给 TimeAxis 显示待办数量）改为 `nextPendingItem` 同源排序后的数组，保证 `pending[0] === nextPendingItem(schedule)`。

### 3.2 演出项跳过预检

`advance()` 的入口预检改为：

```ts
const first = nextPendingItem(scheduleRef.current);
const pf = first && first.kind !== 'show' ? preflightAction(runRef.current, first.actionId) : null;
```

与 `settle.ts` 的 `if (item.kind === 'show') continue`（在 preflight 之前）保持同口径。
**一票否决**：把 show 项也纳入预检。

### 3.3 顶栏徽章恢复

- 拦下时改为 `setLastStop(pf.reason)`（不再传空串）。
- `STOP_TEXT` 补 `times: '次数用完了'`（≤8 字）。
- `styles.css` 补 `.tlx-status.times { background:#fdecec; color:#c0392b; }`（与 stamina/money 同色系）。
- **禁止**把完整句子塞进 `.tlx-status`：`.tlx { overflow: hidden }` + 徽章 `absolute/nowrap/left:50%`，
  超过约 14 字会被两端裁成半句（T-031 已实测踩过一次）。

### 3.4 主区警示条（本单主体）

位置：`.col-center` 内、`<TimeAxis>` 之后、`<section className="mod-main">` 之前。

结构（语义类名固定）：

```tsx
{advanceBlock && (
  <section className="mod mod-block-bar">
    <span className="block-bar-ico">!</span>
    <p className="block-bar-text">{advanceBlock.text}</p>
    <button className="block-bar-go" onClick={() => { setMainTab('plan'); }}>去安排行程</button>
    <button className="block-bar-x" onClick={() => setAdvanceBlock(null)} aria-label="关闭">×</button>
  </section>
)}
```

要求：

- 红色系（`--danger` 若有则用，否则 `#c0392b` / 底 `#fdecec` / 边 `#f3c7c3`），高度约 40px，圆角与 `.mod` 一致。
- 文案＝**原因 + 哪一条 + 差多少**，例如：
  - `「专业歌唱指导」体力差 20，这一条排在队首，推不动。`
  - `「街头演出」钱差 ¥120，这一条排在队首，推不动。`
  - `「兼职打工」本局次数已用完（每局 1 次），删掉它后面的行程才能走。`
- 出现在**任何 tab** 都能看到（它是 `.col-center` 的直接子元素，不在某个 tab 的内容里）。
- 淡入 120ms（`@keyframes` 或 transition 均可），不要遮挡、不要撑高其他模块（`flex: 0 0 auto`）。
- 点「去安排行程」→ `setMainTab('plan')`，**横幅保持可见**（它还成立，且玩家就是去解决它的）。

### 3.5 文案单一来源

抽纯函数（建议 `packages/client/src/components/block-text.ts`，或 core 若更合适）：

```ts
export function advanceBlockText(pf: PreflightResult, actionName: string, scopeWord?: string): string
```

- 主区横幅与 `PlanPanel` 的 `.plan-blocked` **共用这一个函数**，禁止两处各写一份。
- `PlanPanel` 现有文案（「下一条「X」体力差 20」）作为短版：函数接受 `{ compact?: boolean }`，
  横幅用完整版（含"推不动/怎么解决"），PlanPanel 用紧凑版。两版必须由同一函数产出，不允许分叉。
- 次数文案里的「本局/本周/今天」按 `ACTIONS[actionId]?.timesScope` 派生，**禁止硬编码**（T-031 已因此退回过一次）。

### 3.6 状态与清除时机

新增 state：`const [advanceBlock, setAdvanceBlock] = useState<AdvanceBlock | null>(null)`。

| 时机 | 动作 |
|---|---|
| `advance()` 命中 preflight | `setAdvanceBlock({ reason, text })` + `setLastStop(reason)` + `setNotice(text)`（日志留痕） |
| `advance()` 校验全过、真正启动 | `setAdvanceBlock(null)` |
| `doStop()` | `setAdvanceBlock(null)` |
| 点「×」 | `setAdvanceBlock(null)` |
| 切换 `mainTab` | 不清除（原因仍然成立，玩家就是去解决它） |
| `run.at` / 排程变化后原因已消失 | 不需要自动清除（下次推进成功时自然清），但**不得**因重渲染闪烁 |

## 5. 守卫（每条必须亲手弄红过一次，记录原文报错）

1. **`nextPendingItem` 排序**：输入乱序（`startAt` 3/1/2）→ 返回 1 那条；空数组 → `null`；全 done → `null`。
2. **`advanceBlockText` 三原因**：stamina / money / times 各一条，断言文案含行动名与差值；
   times 断言含 `timesScope` 派生词（`本局/本周/今天`），且**不**出现硬编码的「每局」。
3. **show 项跳过预检**：构造 `kind:'show'` 的队首项 + 一个 preflight 必败的状态 →
   `advance` 的预检结果为「不拦」（可抽成纯函数 `preflightOfNext(schedule, run)` 便于测）。
4. **拦截必须写 lastStop**：断言拦下后 `lastStop` 非空串（可用纯函数或组件测试覆盖）。
