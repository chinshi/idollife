## P0-1 空位在 d=8 就被 NPC 填满（我实测出来的）

用 `scheduleWeek(3, 3, 'seed-abc')` 取三线 4 顺位场次，逐日算 `npcOccupied`：

```
d=60  占=          空位=1,2,3,4
d=42  占=1         空位=2,3,4
d=25  占=1,2       空位=3,4
d=15  占=1,2,3     空位=4
d=8   占=1,2,3,4   空位=（空）
d=7   占=1,2,3,4   空位=（空）
```

**问题**：`ratio = 0.85` 那一档 `ceil(4 × 0.85) = 4`，于是 **d=11 开始就一个空位都没有**，而报名截止写的是 d=7。等于「提前 4 天静默关窗」，玩家会以为还能报。

**要求**：`ratio < 1` 的档位必须**至少留 1 个空位**，只有 `d ≤ 7` 才允许填满：

```ts
const count = ratio === 1 ? n : Math.min(n - 1, Math.ceil(n * ratio));
```

注意 `n = 1`（单顺位通告）要单独处理：`n - 1 = 0` 会让 `min` 恒为 0，单顺位场次永远不填 —— 那种场次应当保持「d>7 有空位、d≤7 填满」，即 `n === 1 ? (ratio === 1 ? 1 : 0) : ...`。

**新增用例**（`shows.test.ts`）：
- 4 顺位场次：`d=8` 时空位数 **≥1**，`d=7` 时空位数 **= 0**
- 1 顺位场次：`d=8` 空位 1，`d=7` 空位 0

**守卫证红**：把 `Math.min(n - 1, ...)` 还原成 `ceil(n * ratio)` → 上面第一条必须红。

## P0-2 「空位·NPC」这个文案会骗人

`ShowPanel.tsx:207`：

```tsx
<em>{mine ? '已报名' : taken ? '空位·NPC' : '空位'}</em>
```

玩家读成「这是个空位，只不过有个 NPC」，但规则是**NPC 占了就不能报**。改成 `NPC 已占`，并且该顺位按钮加 `disabled`（`taken && !mine` 时），点击时若已被占直接提示「这个位置已经被占了」，不要只是切换选中项。

同时：`taken` 的顺位即使被选中，卡片底部也不该显示「报名」——现在只有 `chk.ok` 把关，`taken` 不参与。把 `taken` 并入按钮禁用条件，文案「位置已被占」。

## P0-3 当天空槽校验没进 core（原验收项 §7.7 缺失）

现在只在 `doBookShow` 里内联算 `used + slot.slots > DAILY_SLOTS`，core 无函数、无测试，别的调用方绕得过去。

**要求**：`canBook` 增加参数 `dayUsedSlots?: number`（默认 0），命中不足时返回新 reason `'day-full'`；客户端改成传当前已用槽数，删掉内联那段。

**新增用例**：当天已用 3 槽 → `canBook` 返回 `day-full`；同条件 `slots=1` 的演出也报不了；`dayUsedSlots=2` + `slots=1` → ok。

**守卫证红**：删掉 `day-full` 分支 → 该用例必须红。

## P1 提成与资格用了两套口径，出现自相矛盾

- 资格：**逐项**比（`reqStats` 每项各自下限）
- 提成：**四项总和**比 `sum(reqStats)`

于是会出现「舞蹈 差 6」却同时显示「含属性提成 +30%，已封顶」。我按实际数据验过：开场要求 15/15/12/12（合计 54），玩家 30/6/30/30（合计 96）→ 提成 `(96-54)/54 = 78%` → 封顶 30%，但舞蹈差 6 根本报不了名。

**要求**：

1. `entryFee`：**任意一项 `reqStats` 不达标 → `uplift = 0`**；全项达标才按总和差算，仍封顶 30%。
2. `ShowPanel` 在 `!chk.ok` 时不显示提成文案，改成 `达标后约 ¥{fee}`（fee 按 uplift=0 算）。

**新增用例**：一项差 1 → `uplift === 0` 且 `fee === baseFee`；全项达标且总和超 50% → `uplift === 0.3`。
