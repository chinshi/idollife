# T-044 去掉饱腹，新增「压力」

> 来源：用户直派（2026-11-05 21:56）
> 原话：「去掉饱腹设定。然后新增一个状态为压力，从 0 增长到 100 的增长大概普通行动 15-20 个行动左右需恢复一次」
> 拍板口径（同日 AskUserQuestion 三问）：
> 1. 到顶就**不能干活**（后续可能用压力做演出成功率判断）
> 2. 减压走**一次清空、低频大额**
> 3. 吃饭保留，定位是**减压 + 心情 + 恢复体力**
> 状态：done

| 层 | 现状 |

## 2. 关键设计判断：压力复用既有的 stress，不新造一条

属性表里**早就有「精神压力」（`stress`）**，归在「负向」组，和焦躁/积劳/情欲/黑历史并列。但它是个死机制：

- `settle` 里有 `stress > 60 → 效率 × 0.95` 的规则
- 但**没有任何行动会给它加值**（行动结果表 0 条）
- 只有 5 种药品作为副作用给一点
- 玩家永远到不了 60，规则从没生效过

所以直接复用它，把 `stress` 从「负向」组挪进「状态」组、改名「压力」，而不是再建一套 `pressure`。理由：

1. 界面上出现「压力」和「精神压力」两个东西是灾难
2. 那条效率规则正好对上用户说的「后续用压力做成功率判断」
3. 药品副作用有地方落，不浪费既有内容

## 3. 数值：为什么爆睡必须不解压

**这是本次最重要的推导。** 如果爆睡也减压，压力永远满不了：

体力 100、爆睡只回 40，玩家每 4~5 条普通行动就要睡一次。若爆睡减压 -35，那压力增长（每条 +6）会被每一次体力补给同时清掉，压力会长期停在低位 —— 这条轴等于白加。

所以恢复手段必须**部分分离**：

- 体力靠**睡**（高频、免费）
- 压力靠**出去玩/吃好的**（低频、花钱）

| 行动 | 花费 | 体力 | 压力 | 定位 |
|---|---|---|---|---|
| 轻活（唱K/宅舞/小剧场/自言自语） | — | -8~-10 | **+5** | 产出 |
| 中活（打工/传单/家教/普通演出） | — | -14~-24 | **+6** | 产出 |
| 重活（商业/单曲/舞台/高强度训练） | — | -26~-36 | **+7** | 产出 |
| 爆睡 | ¥0 | +40 | **0** | 只解乏 |
| 洗澡 | ¥60 | +15 | **-8** | 便宜的日常小放松 |
| 吃饭·萨莉亚 | ¥80 | +8 | **-12** | 吃顿好的 |
| 吃饭·寿司郎 | ¥220 | +20 | **-22** | |
| 看病 | ¥300 | +15 | **-5** | 治病不治心 |
| 吃饭·好点的 | ¥520 | +28 | **-32** | |
| 游乐园 | ¥400 | -12 | **-50** | 主要减压手段 |
| 卧床 | ¥0 | +55 | **-15** | 躺平 |
| 旅行 | ¥1800 | +15 | **-100** | **一次清空** |
| 食物道具（44 个） | ¥6~¥300 | — | **-3 ~ -25** | 按价格梯度，用钱换时间 |

减压量与花费严格挂钩：想清空压力就得掏 ¥1800 去旅行，日常只能靠 ¥60 的洗澡慢慢滚。

## 4. 到顶的规则

- 压力 ≥ 100：**产出行动（growth / work / performance / 演出预约）一律不能执行**，preflight 返回 `reason: 'pressure'`
- 恢复行动（recover 全类）**任何时候都能做**，否则玩家会被锁死
- 排程执行时遇到压力满：停下，`stoppedReason = 'pressure'`，不会一路跑到 7 天
- 60 ≤ 压力 < 100：行动收益 × 0.95（既有规则，T-044 起才真正有机会触发）

## 5. 节奏验证（真实结算跑出来的数字）

模拟一个真实玩家：体力见底就爆睡、否则继续做同一条产出行动，统计做到压力满需要多少条：

| 行动档位 | 产出条数 | 需要的爆睡次数 |
|---|---|---|
| 轻活 vocal-karaoke（-10 / +5） | **20 条** | 3 次 |
| 中活 work-part-time（-20 / +6） | **17 条** | 6 次 |
| 重活 vocal-coach（-28 / +7） | **15 条** | 8 次 |

正好落在用户要的「15-20 个行动」区间。按一天 3 个行动算，**约 5~7 个游戏日要安排一次减压**。

## 6. 顺带修掉的一个真 bug

数据里有 5 处条件写成 `neg.stress >= 40` / `neg.fatigue >= 50` / `neg.desire` / `neg.scandal`。

`expr-rules.js` 的 `GROUP_PREFIXES` 一直允许 `neg` 前缀（所以 `check:data` 不报错），但 `buildExprData` **从来没提供 `neg` 对象**，于是这些条件**全部恒为 false** —— 4 个剧情事件（失眠、评论战等）一直触发不了。

已在 `buildExprData` 补 `neg: state.negatives`。这是"校验器认、求值器不认"造成的静默失效，比报错更难发现。
