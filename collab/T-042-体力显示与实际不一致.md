# T-042 体力显示与实际不一致

> 来源：用户直派（2026-11-05 10:06）
> 原话：「体力在属性tab和状态栏的显示不太对，爆睡没有加体力，而且0体力的时候也正常执行了唱K行动」
> 状态：done

## 1. 查到了什么

先读线上真实存档（`idollife_runs`，只读）对照，再在本地起真实服务端跑场景。

**爆睡确实在加体力，但只加一半。** 线上 rev=137 的日志连续三条：

```
rest-sleep  staminaΔ=+20
rest-sleep  staminaΔ=+20
rest-sleep  staminaΔ=+20
rest-sleep  staminaΔ=+40   ← 饱腹恢复后才给满
```

配置表里爆睡的 `effects.stamina` 是 **+40**，文案也写着「（体力 +40）」。
差的 20 点是 `settle` 里的饥饿惩罚：

```ts
const staminaApplied = staminaCost > 0 && nextSatiety < 20 ? Math.round(staminaCost * 0.5) : staminaCost;
```

而这个玩家 `satiety` 长期在 0~35（爆睡本身还要 -8 饱腹，越睡越饿），所以几乎每次都吃一半。

**问题不在结算，在于"没人告诉他"**：
- 行程卡预览 `previewAction()` 返回的是配置原值 **+40**
- 日志文案直接用配置表 text，也写 **+40**
- 属性面板/状态栏显示的是结算后的真实值（只涨 20）

→ 玩家看到的就是「预演说 +40、面板涨 20」= 显示不对、睡完没加。

**0 体力跑唱 K 没能复现。** 真实服务端四种场景实测：

| 场景 | 结果 |
|---|---|
| 0 体力 + 爆睡 | 执行，体力 0 → 38（+40，扣 2 点常规事件） |
| 0 体力 + 爆睡 + 唱 K | 两条都执行，0 → 28（+40 -2 -10） |
| **0 体力 + 只有唱 K** | **一条都不执行，`stoppedReason='stamina'`** |
| 体力 100 + 唱 K | 执行，100 → 93 |

也就是说 preflight 是拦得住的。玩家看到"执行了"，可能是同一批排程里前面的爆睡/吃饭先把体力补回来了，或者看到的是日志里的历史记录。

## 2. 顺手补的防御（真漏洞）

`preflightAction` 用 `state.stamina + preview.stamina < 0` 判断，但**如果字段是 undefined**，`undefined + (-10)` 是 `NaN`，`NaN < 0` 恒为 `false` → **永远拦不住**。

线上 25 条记录里有 21 条缺 `mood`/`satiety`（老档），虽没查到缺 `stamina` 的，但这条路径一旦踩中就是"体力无限"。同样问题在 `money` 上（证红时实测：去掉兜底后 `expected true to be false`，确实放行）。

修法：
- `preflightAction` 里 `stamina` / `money` 先 `Number.isFinite` 兜底（stamina → 上限，money → 0）
- `settle` 入口对 `stamina` 兜底，避免把 `NaN` 一路算进库里
