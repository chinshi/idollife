## 二、目标口径（本次改造的语义边界，实现不得偏离）

1. **交互权威在本地，存档权威在服务端。**
   - 运行期间：点击立即改本地状态并返回，服务端交互降级为**后台事件上传**。
   - 读路径（刷新 / 开屏 / 重新进入页面）：`await` 服务端确认，允许 loading，这一步是**唯一**的权威校准点。
2. **运行期间禁止反向校准。** 后台上报回来的 `mismatch / stale / too_fast / adjusted` 一律**不改 UI**（只更新 revision）；只有 `taken_over` 允许中断（多端互斥是安全语义，不能乐观）。
3. **启停与结算走同一条串行 outbox。** 顺序天然正确：start 事件一定先于它之后产生的 sync 快照到达服务端，杜绝 `too_fast` 误杀。
4. **事件幂等。** 每个事件带 `eventId`（uuid），服务端已处理过就返回当前快照，不再二次结算。
5. **对账原则「宁少不多」。** 客户端上报的 `at` 是玩家真实看到的位置；服务端不得用「自己 catchUp 到 now」的结果覆盖它，只能用上界校验拒绝超量。

## 三、实现要求

### 3.1 core（`packages/core/src/clock.ts`）

新增纯函数（供 server 复用，禁随机 / 时间 / DOM）：

```ts
/** 用「本次运行时长」校验一段推进是否合法：不受网络延迟影响 */
export function elapsedBudget(elapsedMs: number, speed: number, timeScale?: number): number
/** = gameAdvance(elapsedMs, speed, timeScale) + 半秒容差 */
```

其余（`gameAdvance` / `clockTarget` / `catchUp`）**不改语义**。

### 3.2 server

新增 `POST /v1/clock/event`：

```ts
interface ClockEventBody {
  runId: string; sessionId: string;
  eventId: string;              // 幂等键，uuid
  type: 'start' | 'stop';
  speed: number;                // type='start' 必填，必须在 ALLOWED_SPEEDS
  at: number;                   // 事件时刻的本地 run.at
  run: RunState;                // 事件时刻的完整本地状态
  schedule: ScheduleItem[];
  runStartAt: number;           // 本次运行开始时的 run.at
  elapsedMs: number;            // 本机时钟测得「本次运行已过多久」，stop 时冻结
  clientTs: number;             // 事件发生本机墙钟（只用于乱序过滤，不做时长计算）
}
```

处理顺序：

1. `getUser` → `loadAndCatchUp(runId, now)`（保留离线补算）。
2. 归属校验、session 校验（非持有者 → 409 `taken_over`，与现有口径一致）。
3. **幂等**：`rec.appliedEvents` 含该 `eventId` → 200 返回当前快照，附 `duplicate: true`。
4. **乱序过滤**：`clientTs < rec.lastEventTs` → 丢弃，返回当前快照，附 `dropped: 'out_of_order'`。
5. **上界校验（用时长，不用绝对时刻）**：
   `at - runStartAt <= elapsedBudget(body.elapsedMs, speed)`。
   - `type='stop'` 时 `runStartAt` 就是本次运行起点，`elapsedMs` 是冻结的本次运行总时长。
   - 通过 → 按 `at` 结算；超出 → 按 `runStartAt + elapsedBudget(...)` 结算，返回 `adjusted: true`（**不报错**，玩家无感）。
6. **结算**：与 `/v1/sync` 同款 `settle(...) + markDone(...) + sameSnapshot` 比对；不一致以服务端重放结果为准，附 `adjusted: true`。
7. **落状态**：
   - `start` → `clock = { status:'running', gameAt: 结算结果, wallAnchor: now, speed, sessionId, updatedAt: now }`
   - `stop`  → `clock = { status:'paused',  gameAt: 结算结果, wallAnchor: 0,   同 speed, sessionId, updatedAt: now }`
8. 写回 `appliedEvents`（只留最近 20 个）+ `lastEventTs`，`revision + 1`。

`/v1/clock/session` 增加**丢失暂停兜底**：请求体可带 `localClock?: ClockState`。
若 `serverClock.status === 'running'` 且 `localClock.status === 'paused'` 且 `localClock.gameAt < 服务端 catchUp 值` → 判为「stop 事件没送到」，按 `localClock.gameAt` 结算成 `paused`，返回 `reconciled: 'lost_pause'`。其余情况行为不变。

`RunRecord` 新增可选字段 `appliedEvents?: string[]`、`lastEventTs?: number`（`store` 的 file/supabase 两个实现都要读写，Supabase 走 jsonb `clock` 同层的整行 json，不需要新加列——**若发现必须加列，先停下来写回执，不要自己动 DDL**）。

`/v1/clock/start` 与 `/v1/clock/pause` **保留**（读路径与旧客户端兜底用），不删。

### 3.3 client

1. **新增 `state/outbox.ts`**：持久化串行队列，`localStorage` 键 `idollife:outbox:<runId>`。
   - 队列元素两种：`{ kind:'clockEvent', ...ClockEventBody }`、`{ kind:'sync', ...SyncRequest }`。
   - `enqueue()` 同步写入内存 + localStorage；`flush()` 串行发送，成功出队，网络错误保留。
   - `flush()` 单飞（不并发）；页面 `visibilitychange → hidden` 与 `beforeunload` 尽力 flush（不保证，靠持久化兜底）。
2. **`advance()`**：本地校验（无待执行 / `pendingEvent`）→ 同步 `setRunning(true)` + 写本地 clock(running) → `enqueue(clockEvent start)` → `void flush()` → **立即返回**。删掉 `rollback` 与 `startPending`。
3. **`doStop()`**：同步冻结快照 → `setRunning(false)` + 写本地 clock(paused, `gameAt = run.at`) → `enqueue(clockEvent stop)` → `void flush()` → **立即返回**。删掉 `await pauseClock`。
4. **切倍速**：同步改本地 `speed` → `enqueue(clockEvent start, speed=新值)` → `void flush()`。**从两次请求降为一次异步上传**。
5. **`reportProgress` / `drainReports` 合并进 outbox**：同步快照 `enqueue({kind:'sync'})`。返回 `ok` 只更新 `revision` / `clockRef` / `scheduleRef`；`mismatch/stale/too_fast/adjusted` **不再 `applyAuthoritative`**，丢弃该条继续；仅 `taken_over` 停 UI。
6. **读路径**：`confirmClockSession()` 前先 `await outbox.flushWithTimeout(1500)`，然后 `POST /v1/clock/session` 带 `localClock`。返回后照旧 `applyAuthoritative`。`reconciled === 'lost_pause'` 时 `setNotice('上次的暂停没送到云端，已按你停下的位置对齐。')`。
7. **本地 clock 持久化**：键 `idollife:localClock:<runId>`，`{status, gameAt, speed, savedAt}`。只用于读路径对账与断网续跑，不参与结算。
8. **时间取用走 `serverTime` 偏移**：session 返回的 `serverTime` 与本地 `Date.now()` 求 `offset`，`elapsedMs` 用 `Date.now() + offset - runStartTs` 计算，防止本机时钟前跳刷进度。

### 3.4 测试（必须新增，且用已知坏样本证红）

`packages/server/tests/clock-api.test.ts` 增补：

2. **幂等**：同一 `eventId` 连发两次 → 第二次 `duplicate:true` 且 `revision` 不变。

5. **乱序丢弃**：`clientTs` 小于 `lastEventTs` 的 start → `dropped:'out_of_order'`，clock 不变。

### 4. 风险点 / 与卡面的偏差

1. **event 走原始记录、不先 `loadAndCatchUp`**：卡面 3.2 步骤 1 写的是先 `loadAndCatchUp`，但 stop 权威性要求「落库 gameAt = 上报 at」，若先 catchUp 到 now 会把 8 秒延迟补算进去（守卫 A 正是证明）。因此 event 直接读原始记录，用 `elapsedBudget` 做上界；读路径（session/latest）仍走 catchUp。离线补算由读路径与旧 start/pause 兜底。
2. **丢失暂停判定用 `clockTarget`**：`rec.clock.gameAt` 只推进到已完成行动边界，用 `clockTarget(rec.clock, now)` 才是「若继续跑会到的位置」；否则本地 paused 等于边界时永远触发不了对账。
3. **outbox 失败重试仅在网络恢复后的下一次 flush**（无定时器）；`beforeunload` 不保证送达，靠 localStorage 队列兜底。
4. **事件响应只更新 revision/clock**，不应用 `adjusted` 重放状态到 UI（按「运行期间禁止反向校准」）；读路径 session 会做权威校准。
5. **本地 clock 只用于读路径对账与断网续跑**，不参与结算；本机时钟前跳由 `serverTime` 偏移 + `elapsedBudget` 双重拦截。
