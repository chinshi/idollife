# T-039-r4 返工单：`mergeAligned` 是差分补丁，必须换成「先对齐再算」

- 编号：T-039-r4
- 状态：`review`（待策划验收）
- 日期：2026-11-04
- 上游：`collab/T-039-r3-状态变更要 rebase 全部字段.md`
- 设计案：`docs/30…md` §2 末尾「**不是差分修补某个字段，而是整份覆盖**」

> r3 的类型收紧了，但 20 个调用点全部写成了 `(base) => ({ ...next, at: base.at })` —— **`base` 只被用来取 `at`，其余字段仍是调用前算好的旧值**。你随后加的 `mergeAligned` 是差分补丁，只合并了 8 个字段，而 `docs/30` 明确写了「不做差分修补」。这条得从结构上解决，不是补字段清单。

`mergeAligned` 合并字段：`money / stamina / mood / satiety / health / stats / log`。

## 1. 结构改法（这一条是命令，不是建议）

### 1.1 唯一的写入助手：先对齐、再算、再提交

```ts
/**
 * T-039：状态变更的唯一入口。
 * 顺序固定：先向服务端对齐 → 用对齐后的 run 作为 base 计算 → 本地应用 → 提交同一份。
 * 全程只算一次，不预演、不合并、不覆盖。
 */
async function pushFresh(
  compute: (base: RunState) => RunState,
  overrideRunId?: string,
): Promise<RunState | null> {
  const token = await getAccessToken();
  if (!token) { setForceLogin(true); return null; }
  const id = overrideRunId ?? runId;

  const aligned = await serverAdvance(id, revision, null, token);
  const base = aligned.kind === 'ok' ? aligned.data.run : runRef.current;
  const expected = aligned.kind === 'ok' ? aligned.data.revision : revision;
  if (aligned.kind === 'ok') applyServerState(aligned.data);

  const next = compute(base);          // ← 唯一的计算点
  if (next === base) return null;      // compute 主动放弃（前置校验失败）
  commitRun(next);                     // ← 唯一的本地应用点

  let res = await putState(id, expected, { run: next, schedule: scheduleRef.current, seed }, token);
  if (res.kind === 'conflict' || res.kind === 'stale_clock') {
    res = await putState(id, res.data?.revision ?? expected, { run: next, schedule: scheduleRef.current, seed }, token);
  }
  if (res.kind === 'ok') { applyServerState(res.data); setSyncStatus('synced'); return res.data.run; }
  return null;
}
```

- **删掉** `mergeAligned`、`rebaseChange`、`previousRunRef`（`commitRun` 里那段记录也删）。
- **删掉** `pushWholeState`（被 `pushFresh` 取代）。
- `compute` 里允许调用 `setNotice`（会被执行一次），**禁止**调用 `commitRun` / `setSchedule` / 发请求。

### 1.2 二十处调用点按下面四类改

**A 类：纯字段变更（无校验无随机）** —— `applyIdolName`、`doSetCity`、`doDebut`、`doAdvanceStage`、`cancelBooking`、`bookShow`、`buy-consume`

```ts
// 改前
const next = { ...base, city };
commitRun(next);
setNotice('城市已切换。');
void pushWholeState((base) => ({ ...next, at: base.at }));

// 改后
void pushFresh((b) => {
  setNotice('城市已切换。');
  return { ...b, city };
});
```

**B 类：core 函数返回 `{ state, result }`（有前置校验）** —— `doReward`、`doAccept`、`doBuy`、`doUnequipBag`、`doUseItem`、`doDivine`、`confirmCreateParty`、`doRecruit`、`doAdvanceStage`

```ts
// 改前
const { state, result } = buyItem(runRef.current, item);
if (result !== 'ok') { setNotice('钱不够。'); return; }
commitRun(state);
setNotice(state.log.at(-1)?.text ?? '');
void pushWholeState((base) => ({ ...state, at: base.at }));

// 改后
void pushFresh((b) => {
  const { state, result } = buyItem(b, item);
  if (result !== 'ok') { setNotice('钱不够。'); return b; }   // ← 返回 base = 放弃写入
  setNotice(state.log.at(-1)?.text ?? '');
  return state;
});
```

`return b` 就会被 `pushFresh` 当成「放弃」，不写库、不改 UI。

**C 类：带随机（`recruit` / `divine`）** —— 随机 seed 必须在 `compute` **外面**算死，保证只调用一次时行为确定：

```ts
void pushFresh((b) => {
  const seedForDraw = `${seed}:recruit:${b.log.length}`;   // 不掺 Date.now()，避免两次不同
  const { state, result } = recruit(b, seedForDraw);
  if (result !== 'ok') { setNotice('招募失败。'); return b; }
  setNotice(state.log.at(-1)?.text ?? '');
  return state;
});
```

**D 类：只提交排程、不动 run** —— `savePlan`、`clearPlan`、`decide`

```ts
// 改前：pushWholeState((base) => base)
// 改后：run 原样返回，等价「只提交 schedule」
void pushFresh((b) => b);   // pushFresh 里 next === base 会直接返回，所以改成显式提交：
```

→ 这三种场景改为**单独** `putSchedule()` 助手（只提交 `schedule`，`run` 用对齐后的原样）：

```ts
async function putSchedule(): Promise<void> {
  const token = await getAccessToken();
  if (!token) { setForceLogin(true); return; }
  const aligned = await serverAdvance(runId, revision, null, token);
  const expected = aligned.kind === 'ok' ? aligned.data.revision : revision;
  const base = aligned.kind === 'ok' ? aligned.data.run : runRef.current;
  if (aligned.kind === 'ok') applyServerState(aligned.data);
  const res = await putState(runId, expected, { run: base, schedule: scheduleRef.current, seed }, token);
  if (res.kind === 'ok') applyServerState(res.data);
}
```

不传 `run` 变更（服务端 `PUT` 允许只给 `schedule`，`run` 沿用记录里的），所以更省：

```ts
const res = await putState(runId, expected, { schedule: scheduleRef.current }, token);
```

**注意**：`PUT` 的 `stale_clock` 只在带 `run` 时校验 `run.at`；只带 `schedule` 时不会触发。确认一下服务端实现，如果只带 schedule 会报 `bad_run` 就带上 `run: base`。
