## 0. 根因（先读，不要跳）

时间流逝看着像坏了，实际是**两个正交的量被合成一个旋钮**：

- `actionMinutes = 10`（一条行动占 10 游戏分钟，`ACTION_MS`）
- `actions` 表「单次分钟」原来还是 **1**（`ed1c399` 只改了前者、没改后者）
- `speed = 1` 的语义是「1 真实毫秒 = 1 游戏毫秒」

于是：一条行动只占槽位的 1/10，**后面空出 9 分钟**；9 分钟游戏时间 = **9 真实分钟静默等待**。
玩家点开始 → 干等 9 分钟 → 闪 1 分钟 → 再等 9 分钟。一天 3 条 = 30 真实分钟。

## 2. core：新增系数与公式单点

### 2.1 `packages/core/src/content.ts`

```ts
/** 1 真实毫秒推进多少游戏毫秒的系数（D-017）。倍速 speed 乘在它之上，两者正交 */
export const TIME_SCALE = Math.max(1, Number(BALANCE.timeScale ?? 20));
```

注意 `BALANCE.timeScale` 可能不存在（旧 `balance.json`），必须有 `?? 20` 兜底。

### 2.2 `packages/core/src/clock.ts`：导出两个纯函数，`catchUp` 改用它们

**当前推进公式在仓库里被抄了三遍**（core `catchUp`、server 水位线、client rAF tick），这是本次最容易漏改的结构。收敛成单一来源：

```ts
/** 真实流逝 elapsedMs 在给定倍速下推进多少游戏毫秒（D-017） */
export function gameAdvance(elapsedMs: number, speed: number, timeScale: number = TIME_SCALE): number {
  const s = Math.max(1, speed);
  const k = Math.max(1, timeScale);
  return Math.max(0, elapsedMs) * s * k;
}

/** running 时钟在 nowWall 时刻的目标游戏时间；非 running 直接返回 gameAt */
export function clockTarget(clock: ClockState, nowWall: number, timeScale: number = TIME_SCALE): number {
  const elapsed = clock.status === 'running' ? Math.max(0, nowWall - clock.wallAnchor) : 0;
  return clock.gameAt + gameAdvance(elapsed, clock.speed, timeScale);
}
```

`catchUp` 里改用 `clockTarget`，并给 `CatchUpOptions` 加可选 `timeScale?: number`（默认 `TIME_SCALE`，供单测与非默认档位使用）。

**然后逐处核对除以 speed 的反推**——`wallAnchor` 的回推现在写的是 `/ speed`，加了系数后必须 `/ (speed * timeScale)`，否则每算一次锚点就偏移 20 倍，进度会疯狂漂移。当前三处：

```ts
// 位置 1：stoppedReason === 'time'
wallAnchor = nowWall - (target - gameAt) / speed;
// 位置 2：executed.length >= maxSteps
wallAnchor = nowWall - Math.max(0, target - gameAt) / speed;
// 位置 3：exhausted 但排程还有未完成项
wallAnchor = nowWall - Math.max(0, target - gameAt) / speed;
```

统一改为先算 `const rate = Math.max(1, speed) * Math.max(1, timeScale);`，再 `/ rate`。

### 2.3 core 单测（`packages/core/tests/clock.test.ts`）

必须新增这三条，且**先证明它们在旧实现下会红**（回执里写清怎么证的）：

1. `timeScale=20` 下，1 真实秒 + speed 1 推进 **20 000** 游戏毫秒；`timeScale=1` 下推进 1 000。
2. **倍速与系数正交**：speed 8 + timeScale 20 的推进量 = speed 1 + timeScale 20 的 8 倍。
3. **分段一致性（回归锚点回推）**：同一段真实时间，`catchUp` 一次算完 与 拆成 5 次算（每次把上次的 `clock` 传回去），
   最终 `clock.gameAt` 与 `run.at` 必须**逐毫秒相等**。这条专门守第 2.2 节那个 `/ rate` 的坑——
   只改 target 不改锚点回推时，它一定会红。

## 3. server：水位线容差按真实时间定义

### 3.1 `packages/server/src/app.ts`

当前（`~312`）：

```ts
const allowed =
  clock.status === 'running'
    ? clock.gameAt + Math.max(0, now - clock.wallAnchor) * clock.speed + 1000
    : clock.gameAt + 1000;
```

改成用 core 的 `clockTarget` + 一个**按真实时间定义**的容差：

```ts
/** 允许客户端比服务端"快"多少真实毫秒（起播往返约 1.2s，留 3s） */
const REAL_TOLERANCE_MS = 3000;

function allowedGameAt(clock: ClockState, now: number): number {
  return clockTarget(clock, now) + gameAdvance(REAL_TOLERANCE_MS, clock.speed);
}
```

必须做到：

- `/v1/sync` 与 `/v1/choice` 的 `too_fast` 判定**都**改用它（`/v1/choice` 现在是 `rec.clock.gameAt + 1000`）。
  两处保留各自的语义：`choice` 仍然要求「不推进时间」，只是容差换成同一尺度。
- 删掉裸的 `+ 1000`。固定 1 游戏秒在 8 倍速 × 20 系数下等于 0.006 真实秒，第一次上报必被拒。

### 3.2 server 单测（`packages/server/tests/clock-api.test.ts`）

新增守卫：`start` 之后模拟**客户端已跑 1.2 真实秒**（8 倍速）再上报，不得返回 `too_fast`。
用旧容差（`+1000`）运行时这条必须红，写清怎么证的。

## 4. client：三处必须跟着改

### 4.1 本地推进公式（`packages/client/src/App.tsx` ~589）

```ts
const target = Math.max(runRef.current.at, anchorGame + (nowPerf - anchorPerf) * speed);
```

改为调用 core 的 `gameAdvance`：

```ts
const target = Math.max(runRef.current.at, anchorGame + gameAdvance(nowPerf - anchorPerf, speed));
```

**这条不改会怎样**：本地按 1 倍速跑、服务端按 20 倍算水位线 → 客户端永远追不上，界面看起来「停住不动」；
反过来漏改服务端则每次上报都被 `too_fast` 打回。两边必须同一个函数。

### 4.2 倒计时显示要换回真实秒（`packages/client/src/components/TimeAxis.tsx` ~99）

现在写的是 `` `还剩 ${Math.ceil(remainMs / 1000)} 秒` ``，`remainMs` 是**游戏毫秒**。
加了系数后一条 10 分钟行动会显示「还剩 600 秒」，实际 **30 秒**就跑完——玩家会以为坏了。

改为真实剩余秒：

```ts
const realSec = Math.ceil(remainMs / (Math.max(1, speed) * TIME_SCALE) / 1000);
```

`progress` / `pct` 用的是比例，**不用改**（比例与尺度无关）。检查 `TimeAxis` 里是否还有别处拿 `remainMs` 直接显示秒数，一并改。

### 4.3 倍速刷新后丢失（`App.tsx` ~275）

```ts
const [speed, setSpeed] = useState(1);   // 1212 行只 setItem，从来没读回
```

改为初始化时读回，并校验白名单（`ALLOWED_SPEEDS` 里没有的值一律回落 1，防止脏 localStorage 让服务端拒绝）：

```ts
const [speed, setSpeed] = useState(() => {
  const raw = Number(localStorage.getItem('idollife:speed'));
  return (ALLOWED_SPEEDS as readonly number[]).includes(raw) ? raw : 1;
});
```

注意服务端 `clock.speed` 才是权威（`confirmClockSession` 已经 `setSpeed(res.data.clock.speed)`），
本地读回只用于**开屏首帧**，别拿它去覆盖服务端值。

### 4. 风险点

1. **legacy 测试语义调整**：T-025/T-026 的 6 条用例加了 `timeScale: 1`，否则默认 20 倍下它们的“15 分钟/30 分钟”时间前提会变化。不是改断言对错，只是把旧用例锁回原尺度；新增 3 条覆盖 20 倍。
2. **容差**：`REAL_TOLERANCE_MS=3000` 是真实时间容差，8 倍速下等于 480 游戏秒；这是卡面要求的“起播 1.2s 往返”余量，若后续要求更严格可调小。
