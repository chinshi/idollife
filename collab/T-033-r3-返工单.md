# T-033 r3 返工单：报名列表的「已宣发」状态

截图这次是真的，所以暴露出了 T-032 起就存在、我上一轮漏掉的问题。

---

## 现象

用真实 `scheduleWeek` 渲染后，「报名演出」列表里 5 张卡全部是「位置已被占」（`.tmpdev/t033-real-0.png`、`t033-real-1.png`）。原因：

1. 列表 filter 是 `d >= -1 && d <= 60`，**把距开演 ≤7 天的场次也收进来了**。
2. 按 NPC 填充曲线，`d ≤ 7` 时 `N` 个顺位全部被 NPC 占满（这是设计好的，因为报名已经截止）。
3. 卡片默认选中第 1 个顺位（`slotIdx = 0`），而第 1 顺位必然已被占。
4. 于是每张卡的按钮都是「位置已被占」。

玩家打开「报名演出」，看到的是一屏报不了的卡片，会认为系统坏了。

---

## 要改的三条

### 1. 「报名演出」列表必须明确区分「可报 / 已宣发」

产品口径（`docs/29` §7、用户原话「到 7 天前空位填满，显示已宣发无法报名」）：

- `d > 7` 且在报名窗口内 → 正常卡片，可抢空位。
- `d <= 7` → **卡片仍在列表里可见**（玩家要知道自己错过了什么），但必须显式标 **「已宣发」**：
  - 卡片右上或状态行加一个 `已宣发` 徽标，卡片整体降透明度（参考当年 `.plan-day.past` 的做法，别用纯灰遮死）。
  - 按钮文案改为「已宣发，报名已截止」，禁用；**不要再出现「位置已被占」**。
- `d > 7` 但所有空位已被 NPC 占满（理论上不该发生，但 4 槽以上在 d=8 会有边界）→ 按钮「本场已满」，禁用。

不要新增 tab，不要拆分列表。用户要求的是"能看到但报不了"。

### 2. 默认选中「第一个可报的顺位」，不是第 1 个顺位

现在 `slotIdx` 初始为 0。改成：进卡片时选第一个 `未被 NPC 占 && 未被自己报名` 的顺位。

- 一个空位都没有 → 不选中任何顺位（`slotIdx = -1` 之类），按钮走「已宣发 / 本场已满」。
- 玩家点了被占的顺位时，仍然提示「这个位置已经被占了」（这条保留）。

这条对 `d > 7` 的普通卡也生效：一张 6 顺位卡如果前 3 个被 NPC 占，进卡默认应该停在「次压轴」那个空位上，玩家直接就能点报名。

### 3. 「已参与」里的单顺位演出显示「主位」，不是「1号位」

`.tmpdev/t033-real-mine.png` 显示 `商务 [大型] 1号位 [已完成]`。

- `slotCount === 1` 的场次（漫画/商务/拍摄/OM）显示 **主位**。
- 多顺位的仍可显示「N 号位」，但更好的做法是直接查该场的 `slotName`（`开场/中坚/次压轴/压轴`）——`SHOW_SLOTS_DEFS` 里已有，按 `showId + slot` 查即可。**两处都用 slotName，统一**。
