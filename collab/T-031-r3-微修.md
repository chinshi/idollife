## 1. `times` 文案硬编码，与配置表自相矛盾（P1，玩家可见）

`packages/core/src/preflight.ts` 现状：

```ts
text: '这条本周的次数用完了（每局 1 次）。删掉它，后面的行程才能接着跑。'
```

问题：
- 「本周」写死，但 `timesScope` 有 `day/week/run` 三档，将来加日限行动就会说错。
- 「每局 1 次」写死，实际 `street-live` 是**每周 2 次**，玩家会看到「本周用完（每局 1 次）」这种自相矛盾的句子。

**要求**：按 `ACTION_META[id].timesScope` 与 `times` 派生（r1 版本里本来有 `SCOPE_WORD` / `SCOPE_UNIT`，别丢）：

```ts
const word = { day: '今天', week: '本周', run: '本局' }[scope] ?? '本局';
const unit = { day: '天', week: '周', run: '局' }[scope] ?? '局';
text: `这条${word}的次数用完了（每${unit} ${times} 次）。删掉它，后面的行程才能接着跑。`
```

**新增 core 用例**（`preflight.test.ts`）：
- `street-live`（week / 2 次）次数用尽 → text **包含** `每周 2 次`，且**不含** `每局`
- 用 `ACTION_META` 反查断言，不许把 `2` 写死在断言里（改成表里换数就该跟着变）

**守卫证红**：把 `times` 换回硬编码 `每局 1 次` → 上面这条必须红。

## 2. 被拦截时清掉残留的停止标签（P2，状态冲突）

`advance()` 拦截分支目前只 `setNotice(pf.text)`。若上一批以 `exhausted` 结束，顶栏还挂着「这一批行程走完了」，和 `notice` 的「体力不够…」冲突。

**要求**：拦截分支里加 `setLastStop('')`（在 `setNotice` 旁边）。仍不许有任何其他副作用（不 setRunning、不入队、不写 localStorage）。
