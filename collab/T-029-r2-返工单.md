────────────────────────────────
【P0-1】新档第一条事件必 404，outbox 队列永久卡死
────────────────────────────────
现象链条（已在代码里坐实）：
- `app.ts` /v1/clock/event：`const rec = await store.getRun(body.runId); if (!rec) return c.json({ error: 'not found' }, 404);`
- `outbox.ts#flush()`：`if (outcome.kind === 'error') return;` —— 不 shift、不继续，整条队列停在这个队头。
- 而 `/v1/sync` 和 `/v1/choice` 都有「记录不存在就创建」的分支，唯独 event 没有。

触发路径（100% 复现）：新用户 / 新设备登录 → 云端无记录 → 加行程 → 点「开始推进」→ start 事件 404 → 之后每条 sync 永远发不出去 → 服务端这一局**从来不存在**，刷新只能回本地 save。

修法（选这个，不要改成客户端丢弃 404，否则新档第一次开始永远不生效）：
- event 路由在 `!rec` 时用 body 创建记录，与 `/v1/sync` 的创建分支同构：`revision: 0`、`clock: createClock(body.at, { sessionId: body.sessionId })`、`run: body.run`、`schedule: body.schedule`、`seed: body.seed`。
- `ClockEventBody` 增加必填 `seed: string`（客户端把当前 `seed` 带上；三个入队点都要带）。校验缺失 → 400 `seed required`。
- 创建后照常走后续结算/落库逻辑，返回 200。

必须补的用例：
「T-029 新档：服务端无记录时 start 事件自动建档」——store 里不放任何记录，直接发 start 事件 → 断言 200、记录已创建、`clock.status === 'running'`、`revision === 1`。

【P0-2】老档 / file store 无 clock → TypeError 500，同样卡队列
────────────────────────────────
`app.ts` event 路由直接 `rec.clock.sessionId`、`rec.clock.gameAt`、`rec.clock.speed`。file store 原样返回 JSON，老档没有 `clock` 字段 → 500 → outbox 卡死。

修法：`const clock = rec.clock ?? createClock(rec.run.at);` 后续全部用 `clock`，与 `loadAndCatchUp` 同口径。`appliedEvents` / `lastEventTs` 一并从兜底后的对象读。

必须补的用例：
「T-029 旧记录无 clock 时 event 不抛错」——记录里删掉 clock 字段，发 stop 事件 → 断言 200 且 `clock.status === 'paused'`。

────────────────────────────────
【P1-1】outbox 无界增长，断网会把 localStorage 撑爆
────────────────────────────────
现状：`enqueueSync` 每条都 push 一份完整 `RunState`（含 log），断网 10 分钟 @1× 就是 20 条；`persist()` 的 catch 把配额错误吞掉，内存队列继续涨，刷新后队列全丢（丢的是「暂停事件」，正是最不该丢的那条）。

修法：
1. 入队 sync 时，若**队尾**已是 `kind === 'sync'`，就地替换而非追加（旧快照到服务端也只会被 stale/too_fast 拒，没有保留价值）。
2. `clockEvent` **永不合并、永不丢弃**。
3. 队列总长上限 60：超出时从头部丢最旧的 `sync`（绝不丢 `clockEvent`）；若全是 `clockEvent` 则保留不动（那是玩家的操作事实）。

必须补的用例（放在 client 或抽成纯函数单测，二选一，不要不测）：
「连续入队 5 条 sync → 队列长度仍为 1，且内容是最新那条」「队列 61 条且头部是 sync → 淘汰后 clockEvent 全部保留」。

────────────────────────────────
【P1-2】elapsedMs 在 ref 为 0 时算出 1.7e12，预算形同虚设
────────────────────────────────
`doStop()` / `queueStopEvent()` 里 `elapsedMs: Date.now() + offset - runStartTsRef.current`，若 ref 还是 0（理论上不该，但作者自己写了 `|| at` 兜底说明不确定）→ elapsedMs ≈ 1.7e12 → `elapsedBudget` 巨大 → 上界校验彻底失效。

修法：抽一个 `measureElapsed(): number`，`runStartTsRef.current <= 0` 时返回 **0**（保守方向：宁可被夹，不可放行）。`runStartAtRef.current` 同理，未设置时用 `at`（此时预算 0+500，安全）。三个调用点统一走它。

不需要新用例，但回执里说明为什么是「保守 0」而不是「信任上报」。
