## 背景（为什么做）

T-009 把「时限」的单位和字段都改对了，首批时限数值也已写进 `content/all.xlsx`（1 天 / 3 天 / 5 天 / 7 天四档，9 条无限期）。但客户端 `TaskPanel` **完全不显示剩余时间**：玩家领下「1 天」的限时通告后，界面上和无限期任务长得一模一样，只能在超时后看到「已过期」——玩家没法做时间决策，限时任务等于没有紧迫感。

这是本轮最后一个「数值能落地但玩家看不见」的空洞，补完它首批时限才算真正上线。

## 需求描述

### 1. core 暴露只读倒计时（唯一真源）

`packages/core/src/tasks.ts` 新增：

```ts
export interface TaskDeadline {
  /** 截止点（游戏时间戳，与 state.at 同口径） */
  deadlineAt: number;
  /** 剩余毫秒；已过截止点时为负 */
  remainingMs: number;
  /** 剩余可用行动次数，向上取整，最小 0（玩家真正消耗的资源单位） */
  remainingSlots: number;
  /** 剩余游戏日，向上取整，最小 0 */
  remainingDays: number;
  /** 已到/已过截止点 */
  due: boolean;
  /** 紧急：剩余 ≤ 1 个游戏日（= DAILY_SLOTS 次行动） */
  urgent: boolean;
}

export function taskDeadline(state: RunState, task: TaskDef): TaskDeadline | null;
```

返回 `null` 的情形（全部要覆盖）：

- `task.deadlineDays` 为 0 或缺失（无限期）
- 未领取（`acceptedAt` 为 0）
- 已完成（`doneAt` > 0）

**注意**：已经 `expired` 的任务**不要**返回 null，要返回 `due: true` 的对象——界面需要显示「已超时」。

计算口径：

- `deadlineAt = acceptedAt + deadlineDays * DAY_MS`
- `remainingMs = deadlineAt - state.at`
- `remainingSlots = Math.max(0, Math.ceil(remainingMs / ACTION_MS))`（`ACTION_MS = ACTION_MINUTES * 60000`；`content.ts` 目前没导出 `ACTION_MS`，请补一个导出，不要在 tasks.ts 里写死 60000）
- `remainingDays = Math.max(0, Math.ceil(remainingMs / DAY_MS))`
- `due = state.at >= deadlineAt`（**注意**：到期判定本身是 `pastDeadline()` 的 `>`，此处 `due` 用 `>=` 表示「时间已到」，两者不冲突，别去改 `pastDeadline`）

**不要**把 `taskDeadline` 塞进 `taskStatus()`。它必须是可单独调用、可被测试直接喂不同 `state.at` 的纯函数。core 依旧禁 `Date.now()`。

### 2. 客户端显示文案（`packages/client/src/components/TaskPanel.tsx`）

只在 `status === 'active'` 与 `status === 'expired'` 的行显示，位置放在 `.task-top` 里状态标签之后、右侧按钮之前（即 `.task-state` 后面紧跟一个 `.task-deadline`）：

**文案按 `status` 分叉，不是按 `due` 分叉**（R2 修订：避免出现「状态写进行中、倒计时写已超时」的自相矛盾行）：

| 情形 | 文案 | class |
| --- | --- | --- |
| `status === 'expired'` | `已超时` | `task-deadline due` |
| `status === 'active' && due` | `期限已到` | `task-deadline urgent` |
| `remainingSlots > DAILY_SLOTS` | `剩 N 次行动 · 约 D 天` | `task-deadline` |
| `0 < remainingSlots <= DAILY_SLOTS` | `剩 N 次行动` | `task-deadline urgent` |

- `N` = `remainingSlots`，`D` = `remainingDays`
- 无限期任务（`taskDeadline` 返回 null）不渲染这个 span，**不要**显示「无限期」占位
- `done` 行不渲染
- `completable` 行也**不**渲染：`statusOf()` 里 `completable` 判定在 `pastDeadline()` 之前，达成条件后就不再过期，奖励是安全的，不需要催
- 给这个 span 加 `title={ '截止：' + dayLabel(deadline.deadlineAt, run.at) }`（`TaskPanel` 已有 `dayLabel` prop，直接复用；只写一行「截止：第N周 周X」，别拼长句）

### 3. 领取前也要能看到时限（R2 新增）

倒计时只在「领了之后」存在，但玩家的时间决策发生在**领取之前**——「这活给 3 天还是 7 天」是决定领不领的关键信息，现在只有领了才看得到，等于把决策信息放在了决策之后。

`.task-req` 里追加一项（放在「任务要求」之后、「奖励」之前）：

```tsx
{task.deadlineDays && task.deadlineDays > 0 ? (
  <span><em>时限</em>{task.deadlineDays} 天</span>
) : null}
```

- 无限期任务整项不渲染（不要写「无限期」）
- 所有状态都显示（含已领取/已完成行也有静态时限，和顶部倒计时并存不冲突：一个是定义、一个是剩余量）

### 4. 样式（`packages/client/src/styles.css`）

紧挨现有 `.task-state.*` 区块追加，**只用现有 CSS 变量**，不引新依赖、不改其它组件样式：

- `.task-deadline`：`font-size: 10px;`、次要色（`var(--muted)`）、`white-space: nowrap;`
- `.task-deadline.urgent`：警示色（与现有 `.task-state.claimable` 的橙红系一致，如 `#b35a00`）、`font-weight: 600;`
- `.task-deadline.due`：`color: #c0392b;`

文案很短，注意 `.task-top` 是 flex 布局：`urgent` 文案变长后不能把右侧按钮挤换行——如需可给 `.task-deadline` 加 `flex: 0 1 auto; overflow: hidden;`。改完请自己看一眼窄宽度下的表现。

### 5. 测试（新增 `packages/core/tests/tasks-deadline.test.ts`）

至少 6 条，**每个数字都要能追到 `DAY_MS` / `ACTION_MS`，不许写死魔法数**：

1. 无限期（无 `deadlineDays`）→ `null`
2. 未领取 → `null`
3. 领取后立刻查：`remainingMs === deadlineDays * DAY_MS`、`remainingSlots === deadlineDays * DAILY_SLOTS`、`urgent === false`（`deadlineDays: 3`）
4. 推进 2 次行动（`+2 * ACTION_MS`）→ `remainingSlots` 恰好少 2；`deadlineDays: 1` 时 `urgent === true`
5. 恰好到期（`state.at === deadlineAt`）→ `remainingSlots === 0`、`due === true`，同时 `taskStatus() === 'active'`（T-009 的 `>` 语义不许被改）
6. 再加 1ms → `taskStatus() === 'expired'`，且 `taskDeadline` 不返回 null、`due === true`
7. 已完成（`doneAt > 0`）→ `null`
8. 剩余 1ms 时 `remainingSlots === 1`（向上取整，不能出现「显示 0 次却还是 active」）
