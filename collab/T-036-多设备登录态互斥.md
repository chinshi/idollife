## 1. 问题（产品所有者实测反馈）

> 「多设备账户登录的场景下，新账户登录点击【在此设备继续】后，没有把老账户的登录状态去掉，导致新老设备一直在反复强夺登录态」

按钮点了没反应（闪一下又被踢回来），老设备完全不受影响，两边一直来回抢。

## 2. 实测根因（四条，全部要修）

### R1 「在此设备继续」是死按钮（客户端已无任何合法接管通路）

- `App.tsx:1888 continueHere()` = `setReadonlyBanner(false)` + `await advance()`。
- `advance()` 走的是**事件通道**：`enqueueClockEvent({type:'start', sessionId, ...})`。
- 服务端 `app.ts:352` 对事件做的是 **「只认主、不改主」**：`clock.sessionId !== body.sessionId` → 409 `taken_over`。
- 结果：`outbox.flush()` 收到 409 → 清队 + `onTakenOver()` → `setReadonlyBanner(true)`。横幅消失→请求→横幅回来，一次点击晃一下。
- 而且 `advance()` 在 flush **之前**已经 `setRunning(true)` + `writeLocalClock(running)`，所以本机先真的跑起来，再被 409 打断——玩家看到的就是「抢了一下又输」。
- **根因**：T-029 把接管能力从 `/v1/clock/start`（无条件写 sessionId）搬到了事件通道，而事件通道按设计不许改主 → 客户端从此没有任何合法接管入口。

### R2 丢暂停对账会强行改主（服务端，不需要点任何按钮）

- `app.ts:252-278`（`/v1/clock/session` 的 `lost_pause` 分支）在**判 holder 之前**就按 `localClock.status === 'paused'` 结算并把 `sessionId: body.sessionId` 写库。
- 被踢的那台只要刷新一次、本地还留着 `paused` 的 localClock，就把主抢回来了 —— **无人操作也会反复**。这是「一直在反复强夺」的直接来源。

### R3 `/v1/clock/start` 无条件改主（重放即可抢）

- `app.ts:173-182` 改了 `sessionId` 却没有任何「这是用户主动接管」的声明，也没有所有权版本校验。
- 任何一次网络失败后的重发、或旧设备队列里的残留请求，只要落到这个接口就把主改回来。

### R4 换账号不隔离本地状态（同一台设备换号 = 老档污染新号）

- `state/save.ts` 的 key 是全局 `idollife:save:v2`，**档里没有任何账号信息**；`sessionId` 存在 sessionStorage，同一个 tab 跨账号复用。
- 新账号登录后 boot 仍用老账号的 `runId` → `fetchLatestRun` 拿到的是新账号的档，但 `localEmpty` 为假、`latest.revision > revision` 也未必成立 → **不采纳云端** → `confirmClockSession(老 runId)` → 403 → 重试一次仍 403 → 顶部「云端时钟读取失败」。
- outbox 队列按 `runId` 存；`syncRun/sendClockEvent` 把 403 归到 `kind:'error'`，`flush()` 遇到 error 直接 `return`（`outbox.ts:122/139`）→ **队列永久卡死**，每次 flush 重试一次、永不丢弃。
- `signOut` 只清 Supabase 会话，不清本地档 / outbox / localClock。
- 边界情况：老账号的档只在本地、云端还没有记录时，新账号 boot 里的 `pushChoice(老 runId)` 会用新账号身份把这个 runId 建档占掉，老账号回到自己设备就是 403。

## 3. 契约

### 3.1 所有权只有一个改入口：显式接管

新增 `POST /v1/clock/takeover`：

```
body: { runId, sessionId, speed }
```

- 校验 user → `rec.userId !== user.id` → 403；`runId`/`sessionId` 必填。
- `loadAndCatchUp(runId, now)`：**以服务端 run/schedule 为底**（禁止采信客户端带来的 run——接管方是落后的一方，采信会丢进度）。
- `!rec.schedule.some(s => !s.done)` → 409 `no_schedule`。
- `rec.run.pendingEvent` → 409 `pending_event`。
- 否则写 clock：
  ```ts
  { ...rec.clock, status: 'running', gameAt: rec.run.at, wallAnchor: now, speed,
    sessionId: body.sessionId, ownerTs: now, updatedAt: now }
  ```
  返回 `snapshot(rec)`（带 `holder: true`、`ownerTs`）。
- `speed` 必须在 `ALLOWED_SPEEDS` 内，否则 400 `bad_speed`。

`ClockState` 增加 **可选** `ownerTs?: number`：最后一次所有权变更的服务端时间，用于回执/排查，**不用于裁决**（客户端时钟不可信）。
写成可选是为了不惊动现有 `ClockState` 字面量与测试夹具；`createClock` 里补 `ownerTs: 0` 即可，不要改成必填。

### 3.2 其他写路径一律不许改主

| 接口 | 规则 |
|---|---|
| `/v1/clock/event` | `clock.sessionId && clock.sessionId !== body.sessionId` → 409 `taken_over`。**即使 body 带 `takeover: true` 也不放行**（一票否决） |
| `/v1/sync` | 同上（现已是，保持） |
| `/v1/clock/pause` | 同上（现已是，保持） |
| `/v1/clock/start` | 改成与事件同口径：非主 → 409 `taken_over`（客户端已不再用它，保留接口给测试；不要在这里开后门） |
| `/v1/clock/session` | 非主 → 返回 `holder:false`，**不结算、不写 sessionId** |

### 3.3 `lost_pause` 必须先判 holder

`/v1/clock/session` 里把 `holder` 计算提到 `lost_pause` 分支**之前**：

- `holder === false` → 直接 `snapshot(rec, { holder:false })` 返回，不进 `lost_pause` 分支，不 `saveClock`。
- `holder === true` → 现有 `lost_pause` 逻辑保持不变（含 `reconciled:'lost_pause'`）。

**一票否决**：保留现状（先写 sessionId 再算 holder）。

### 3.4 客户端接管（`continueHere` 整体重写）

- 新增 `api/sync.ts#takeoverClock(runId, sessionId, speed, token)` → 打 `/v1/clock/takeover`，返回 `ClockOutcome` 同构结果。
- **不入 outbox**：这是用户主动动作，必须是一次性直连请求，失败就提示重试，不许排队重放（否则又变成自动抢）。
- `continueHere()`：
  1. `setTakingOver(true)`；**不要**先 `setReadonlyBanner(false)`。
  2. `const res = await takeoverClock(...)`。
  3. `ok` → `applyAuthoritative(res.state, res.schedule, res.clock, res.revision)`；`runStartAtRef = clock.gameAt`；`runStartTsRef = Date.now() + serverOffsetRef`；`batchRef = null`；`setSnapshot({run, schedule})`；`writeLocalClock(running)`；`setRunning(true)`；`setReadonlyBanner(false)`；`setAdvanceBlock(null)`；notice「已在本设备接管，另一台设备已退出登录。」
  4. `no_schedule` → notice「没有待执行的行程，先安排行程再接管。」，**保持只读**。
  5. `pending_event` → notice「先处理重点事件再接管。」，保持只读。
  6. `error` / `bad_speed` / `unauthorized` → `setClockSyncError(true)` + notice「接管失败，另一台设备仍是当前持有者。」，**保持只读**。
  7. `finally` → `setTakingOver(false)`。
- 横幅按钮：`takingOver ? '正在接管…' : '在本设备继续（另一台会被退出）'`，`disabled={takingOver}`。

### 3.5 被踢的一方要「真的退出」

`onTakenOver` 回调：

- `setRunning(false)`；`batchRef = null`；`setSnapshot(null)`；`writeLocalClock(runId, {status:'paused', gameAt: runRef.current.at, speed})`；
- `setReadonlyBanner(true)`；notice 改「账号已在另一台设备继续，本设备已转为只读。」

只读态必须**堵住所有本机写入口**，否则又是「本地先改、请求被 409、状态被拉回」的抖动：
`advance()` / `doStop()` / `savePlan()` / `cancelPlan()` / `clearPlan()` / `bookShow()` / `cancelBooking()` / `pushChoice` 相关入口，开头统一：

```ts
if (readonlyBannerRef.current) { setNotice('本设备已退出登录，先点「在本设备继续」接管。'); return; }
```

`readonlyBanner` 需要一份 ref（`readonlyBannerRef`）供回调读取，不要依赖闭包里的旧 state。

### 3.6 换账号隔离

1. `SavePayload` 加 `ownerId?: string`；所有 `writeSave(...)` 调用处写入当前 `user?.id`。
2. `state/save.ts` 新增纯函数：
   ```ts
   /** ownerId 缺失（老档）或与服务端账号一致 → 可用；属于别的账号 → null（当作没有本地档） */
   export function resolveBootSave(boot: SaveV2 | null, userId: string | null): SaveV2 | null
   ```
   `userId` 为 null（未登录）时原样返回。
3. boot（`App.tsx` 拉云端那个 effect）里：`boot.ownerId && user.id !== boot.ownerId` 时
   - `clearSave()`（老档属于别的账号，别让本账号的写把它覆盖成混档）；
   - 用 `createSave(initialRun,'run-demo')` 重置 `runId / run / schedule / revision / seed`，**不许复用老 runId**；
   - notice「检测到另一个账号的本地存档，已切换。」
   - 再照常 `fetchLatestRun` 采纳本账号云端档（`localEmpty` 直接成立）。
4. 退出登录包一层 `doSignOut()`：`void flushWithTimeout(800)` → `clearSave()` → 新增 `resetOutbox()`（清当前 runId 队列 + 内存队列）→ 清 `idollife:localClock:<runId>` → `signOut()`。**不清云端任何数据**。
5. outbox 收到 **403** 视为终态：`SyncOutcome` / `ClockEventOutcome` 增加 `{ kind:'forbidden' }`；`flush()` 命中 → `queue = []; persist(); cfg.onForbidden()` 并 return。客户端 `onForbidden` → notice「这一局属于另一个账号，本地缓存已清空。」+ 触发一次 `retryClockSession()`。

## 5. 守卫（每条必须亲手弄红过一次，记录原文报错）

1. **事件不许改主**：A 起跑 → 用 B 的 sessionId 发 `/v1/clock/event` → 409 `taken_over`，且 `clock.sessionId` 仍是 A。
2. **接管真的换主**：调 `/v1/clock/takeover`（B）→ 200 且 `clock.sessionId === B`、`ownerTs > 0`；随后 A 发事件 → 409；B 发事件 → 200。
3. **`lost_pause` 不抢主**：非 holder 带 `localClock{paused, gameAt 更小}` 调 `/v1/clock/session` → `holder:false`，且 `clock.sessionId` 与 `clock.gameAt` 均未变。
   （证红方式：把 holder 判断挪回 `lost_pause` 之后 → 该用例必须变红）
4. **`resolveBootSave`**：`ownerId` 缺失 → 返回原档；`ownerId === userId` → 原档；`ownerId !== userId` → `null`。
5. **reject 分类**：403 → `forbidden`（不是 `error`）。
6. **只读态拦截**（可抽纯函数或直接断言 handler 的 notice）：`readonlyBanner = true` 时 `advance()` 不产生任何 `enqueueClockEvent`。
