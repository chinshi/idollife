【P0-2】"执行中"误判：过去没执行的项全被标成执行中
────────────────────────────────
`PlanPanel.tsx:110`：`const executing = !item.done && item.startAt <= run.at;`
玩家第 5 天，第 2 天有个没跑掉的项 → `startAt(第2天) <= run.at(第5天)` 成立 → 一个**过去的灰格子**上蹦出橙色 outline + "执行中"。这是明显的状态谎报。

修法：`const executing = !item.done && item.startAt <= run.at && run.at < item.endAt;`
（只有 at 真落在 [startAt, endAt) 区间里才算正在执行——和 settle 的判定口径一致。）

顺手确认：`past` 天里存在未执行项时，视觉上要不要额外提示由你判断，但**不能显示"执行中"**。

【P1-3】初始定位在「数据晚到」时会错位
────────────────────────────────
`useEffect(..., [])` 只在 mount 跑一次。但首渲染时 `run` 可能还是本地旧档或 initialRun，随后 `fetchLatestRun` 把云端档设进来 → `currentDay` 从 1 跳到 10，此时滚动还停在 day(-1→0)，**不会重新对齐**。

修法：定位 effect 改成能跟随数据到位，但不能打扰玩家：
- 加 `const dirtyRef = useRef(false)`，容器的 `onScroll`（程序滚动的除外）与 `onWheel` 里置 `true`；
- effect 依赖 `[currentDay]`，内部：`if (dirtyRef.current) return;` 然后定位到 `max(0, currentDay - 2)`。
这样：mount 定位 ✓ / 数据晚到且玩家没动过 → 重新对齐到新的前天 ✓ / 玩家自己滚过 → 不再被拽走 ✓。

注意：程序化 `scrollLeft` 赋值也会触发 `onScroll`，要避免自己把自己标脏（用 rAF 或一个 `programmaticRef` 窗口期内忽略）。
