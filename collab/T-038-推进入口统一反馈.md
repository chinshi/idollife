# T-038 推进入口统一反馈（不再"点了没反应"）

- 状态：done（策划自查自修，未提交）
- 来源：用户 2026-11-04 报障「清空了行程排了爆睡，应该可以推进才对」
- 关联：T-031（preflight）、T-035（只治了 preflight 一条出口）、T-036（只读拦截）

## 1. 现象

用户清空行程 → 排一条「爆睡」（`rest-sleep`，`times=0`、体力消耗 0、效果 +40）→ 点「开始推进」，**界面上没有任何反应**：按钮仍显示「开始推进」、没有红条、没有弹窗。

用户据此怀疑「还没开始的行程是不是不让改」。**这个怀疑不成立**：`removeItem` / `clearPlan` / `addAction` 都不看 `startAt`，未开始项可任意删改。

## 2. 排查结论

用真实 `placeAction` + `preflightNext` + `settle` 跑了 5 种时间点（今天空槽 3 / 空槽 2 / 已满转明天 / 停在槽中间 / 全空），0 体力下**全部** `预检=ok → 执行 → 体力 0→40`。核心结算与落位对这条路径是干净的。

问题在客户端：`advance()` 有 5 个出口，其中**只有 preflight 那条会出横幅**（T-035 做的），另外 4 条：

| 出口 | 原来给玩家的反馈 |
|---|---|
| `blockIfReadonly()` | 只 `setNotice`（日志模块底部小字）+ 只读横幅 |
| `running` | **完全静默 return** |
| 待办 0 | 只 `setNotice`（小字） |
| `pendingEvent` | 只 `setNotice` + 尝试开事件框 |

而「写着开始推进 + 点了没任何显示」在现行代码里只有一种可能同时成立：**按钮是 `disabled` 的**（`TimeAxis.tsx:154` `disabled={pendingCount===0 \|\| running}`）——即待办为 0，爆睡没进排程。其余出口都会留下可见痕迹。

## 3. 改法

1. `components/advance-block.ts` 新增纯函数 `advanceGate({ readonly, running, pendingCount, hasPendingEvent })`，返回 `AdvanceBlock | null`；四条拦截各有非空文案（只读 → 点「在本设备继续」；运行中 → 等或停止；待办 0 → 去安排行程；重点事件 → 先处理）。
2. `App.tsx#advance()` 去掉原来的 `blockIfReadonly()` / `if (running) return` / 待办 0 静默分支，统一走 gate → `setAdvanceBlock` + `setNotice` + `dbg`。
3. `advance()` 入口加一行诊断日志：
   `推进入口 at=… 待办=N 队首=id/actionId@startAt running=… 只读=…`
   以后玩家贴一行日志即可判定是「没排上」还是「被拦」。

## 5. 遗留（下一单，未做）

- **本地行程改动没有落地服务端**：`addAction` / `removeItem` / `clearPlan` / `toggleStop` 只改内存；服务端那份 `schedule` 只在「开始推进」的事件与每次执行后的 sync 里更新。而 `onSync` 成功（`App.tsx:641`）与 `applyAuthoritative`（`:370`，刷新 / 开屏时钟确认 / 接管都会走）会**无条件用服务端旧副本覆盖本地**。即：改完行程、还没点推进之前只要发生一次成功同步，改好的行程会被旧副本还原（看起来像"改了没用"）。
