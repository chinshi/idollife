## 1. 背景：五个具体问题

产品所有者提了 5 条，都是**列表可用性**问题，不是数值问题：

1. **占位节奏不对**。现在是 60 天线性阶梯（`d>45→0%`、`45→25%`、`30→45%`、`20→70%`、`10→85%`、`≤7→100%`）。
   玩家第 55 天打开，一半位置已经没了；而真正该紧张的**截止前一周**反而没什么变化。
   要改成：**平时全空，压力集中在报名截止（d=7）前的 7 天里爆发式填满**。
2. **已占 / 空位长得太像**。现在只差 `opacity: 0.6`，扫一眼分不出来。
3. **满员/已宣发的场次混在列表顶部**，占了最好的位置却点不动；标签文字是「本场已满」，和产品口径
   的「已满」不一致。
4. **一张卡占满整行**，一屏只能看 3 场，横向全浪费。
5. **属性要求平铺在卡片上**，每张卡塞 6 个「够/差 N」，扫不动也看不出重点。要改成：
   **卡面只给结论（名称 / 状态 / 时间 / 空位），点开弹窗看顺位与细则**。

## 2. 占位曲线（core，唯一数值变更）

### 2.1 新曲线

`d` = 距开演天数；报名截止 = `d <= 7`（已宣发）。

| d | 填充比例 |
|---|---|
| d > 14 | **0** |
| 14 | 0.05 |
| 13 | 0.15 |
| 12 | 0.28 |
| 11 | 0.42 |
| 10 | 0.56 |
| 9 | 0.70 |
| 8 | 0.85 |
| d ≤ 7 | 1 |

- 填充量：`ratio >= 1 ? n : Math.min(n - 1, Math.round(n * ratio))`
- `n === 1` 时 `ratio < 1` 恒为 0 → **单顺位通告在截止前一定还能报**（不许在 d>7 就全满）
- 填充顺序不变：**从顺位 1 往上填**（开场先满、压轴最后满），玩家已占的位不参与 NPC 分配
- 曲线形状理由：截止前的最后 7 天（d=14…8）承担全部压力；10 天内变化最快（0.56→0.70→0.85），
  玩家「今天犹豫、明天没位」的紧迫感来自这一段

### 2.2 实测参考（n=4 / n=1 / n=18）

| d | n=4 | n=1 | n=18 |
|---|---|---|---|
| 20 | 0 | 0 | 0 |
| 15 | 0 | 0 | 0 |
| 14 | 0（0.2→0） | 0 | 1 |
| 13 | 1 | 0 | 3 |
| 12 | 1 | 0 | 5 |
| 11 | 2 | 0 | 8 |
| 10 | 2 | 0 | 10 |
| 9 | 3 | 0 | 13 |
| 8 | 3（留 1 个空位） | 0 | 15 |
| 7 | 4（满） | 1（满） | 18（满） |

### 2.3 契约

- `packages/core/src/shows.ts` 新增并导出 `npcFillRatio(d: number): number`
- `npcOccupied` 改为调用它，**签名与返回类型不变**（`Set<number>`）
- 禁止在 client 里重算曲线；禁止把比例写成数组硬编码在组件里

## 3. 列表与卡片（client）

### 3.1 排序权重（在 `ShowPanel` 的 `occurrences` 排序里）

按「状态优先，其次时间」：

| 权重 | 状态 |
|---|---|
| 0 | 我已报名（本场有我，且未取消） |
| 1 | 可报名（还有空位 + 未截止） |
| 2 | 已满（无空位 + 未截止） |
| 3 | 已宣发（`d <= 7`） |

同权重内按 `daysUntil` 升序（快到期的靠前）。**不分区、不折叠**，就是单纯排到后面。

### 3.2 标签文案（必须逐字）

- 满员：`已满`
- 截止：`已宣发`
- 两个都是 `show-badge`，`已满` 走灰底（`.status-full`），`已宣发` 走浅橙底（`.status-announced`）

### 3.3 卡面只留这 6 项

```
┌──────────────────────────────┐
│ 城东 Live House 拼盘   [拼盘][普通][已满] │
│ 第4周 周六 · 开演 3 天后 · 报名截止 6 天后   │
│ 空位 0 / 4                                   │
│ 点击查看详情 ›                                │
└──────────────────────────────┘
```

- **不再**在卡面显示：顺位块、名气/属性「够/差」、出场费、报名按钮
- 时间行格式：`{dayLabel(startAt)} · 开演 {d} 天后 · 报名截止 {max(0,d-7)} 天后`；
  `d <= 7` 时后半段换成 `报名已截止`
- 空位行：`空位 {可报数} / {总顺位}`，可报数 = 总顺位 − NPC 已占 − 我已占
- 整卡是 `<button type="button" className="show-card">`，点击打开详情弹窗
- `已宣发` 卡整体降透明（保留现有 0.62），`已满` 卡不降透明（它只是没位，不是过期）

## 4. 详情弹窗（新增 `ShowDetailModal`，放 `ShowPanel.tsx` 同文件或 `show-detail.tsx`）

用现成的 `Modal`（`import { Modal } from './Modal'`），传 `wide`。

### 4.1 结构（自上而下）

1. **标题行**：演出名 + `[类型]` `[级别]` `[已满/已宣发]`
2. **时间行**：`{dayLabel} · 开演 {d} 天后 · 报名截止 {dd} 天后`（`dd = max(0, d-7)`，d≤7 显示「报名已截止」）
3. **顺位竖列表**（**竖状，不再横排**）：每个顺位一行，行内四段：

```
┌────────────────────────────────────────────────────────────┐
│ 压轴  名气 600 · 演唱 55 · 舞蹈 50 · 演技 45 · 口才 40   ¥1,170 │
│       粉丝 8000 · 成员 3                                    │
│                                              [NPC 已占 / 选这个] │
└────────────────────────────────────────────────────────────┘
```

- **要求显示「要求的值」**，不显示「差 N」；
- 未达标的项**该数值文字标红**（新增 `.req-bad { color: #d93a2b; }`），达标的用默认灰黑；
- 达标与否用 `checkBooking(run, party, occ, slot)` 判定（**不许自己再写一遍比较逻辑**）；
- 每行右侧显示该顺位的出场费 `¥{fee}`（`entryFee`）；
- 状态三态，样式必须**一眼可辨**：

| 状态 | 视觉 | 交互 |
|---|---|---|
| 空位（可报） | 白底 + 1px 实线 `var(--line)` + 左侧 3px 主色竖条 + 右侧「选择」按钮 | 可点，选中后整行 `outline: 2px solid var(--accent)` + 浅橙底 |
| NPC 已占 | **灰底 `#eceef2` + 斜纹背景 + 文字 `#9aa1ab` + 「NPC 已占」** | 不可点，`cursor: not-allowed` |
| 我已报名 | 浅橙底 + 左侧主色竖条 + 「你已报名」 | 不可点（取消走「已参与」tab） |

- 斜纹写法示例：`repeating-linear-gradient(45deg, #e6e9ee 0 6px, #eff1f5 6px 12px)`
- **禁止只靠 `opacity` 区分已占与空位**（现状 `opacity: 0.6` 不够，必须换底色 + 斜纹 + 文案）

4. **报名细则块**（`.show-rules`，小字灰底块），逐条列：
   - `报名截止：开演前 7 天，之后转为已宣发、不再接受报名`
   - `同一天只能报一场演出`
   - `取消规则：距开演 ≤15 天取消扣 60% 出场费；≤7 天不可取消`
   - `出场费按属性超出要求的幅度提成，最多 +30%`

5. **底部操作条**（`.show-detail-foot`）：
   - 左：`出场费 ¥{fee}`（未达标显示 `达标后约 ¥{fee}`）+ `含属性提成 +{pct}%，已封顶`（`uplift>=0.3` 时补这句）
   - 右：`报名` 按钮（`className="primary"`），disabled 文案沿用现有六种：
     `已宣发，报名已截止` / `本场已满` / `位置已被占` / `这天已有安排` / `这天行程排满了` / `条件不足`
   - **判定一律复用** `canBook` + `checkBooking` + 现有的 `dayTaken` / `dayUsed` 计算，不许新写分支

### 4.2 选中默认值

- 打开时默认选中 `firstOpenSlotIndex(occ, npc, mineSlots)` 的结果
- 返回 `-1`（全占）时选中下标 0，但按钮一定是 disabled 状态，文案走 `已满` 分支

### 4.3 弹窗数据必须是活的

`npc` 用 `npcOccupied(occ, run.at, mineSlots)` 现算，**不许把列表里的 `npc` 快照当 props 传进来**——
玩家挂着页面推进时，弹窗里的占用状态要随 `run.at` 变化重算。
