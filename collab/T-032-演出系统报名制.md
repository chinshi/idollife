**刷新规则**（必须严格按此，别自己发明）：

| 城市 | 周末场 | 周中场 |
|---|---|---|
| 三线 | 1 | 0 |
| 二线 | 2 | 0 |
| 一线 | 4 | 0 |
| 超一线 | 4 | 1～2（随机） |

- 只从 `cityTier === run.city` 的演出里抽；`visibleCond` 不满足的剔除。
- 节日周（`festival !== 'none'` 的演出）：该周额外出 1 场。
- 抽不齐（池子不够）就少出，不重复同一场。

**NPC 填充曲线**（`d = daysUntil`）：

| d | 占用总数 |
|---|---|
| d > 45 | 0 |
| 45 ≥ d > 30 | `ceil(N * 0.25)` |
| 30 ≥ d > 20 | `ceil(N * 0.45)` |
| 20 ≥ d > 10 | `ceil(N * 0.70)` |
| 10 ≥ d > 7 | `ceil(N * 0.85)` |
| d ≤ 7 | `N` |

- 从顺位 1 往上填，跳过玩家已占的位（开场先满、压轴最后满）。
- `d ≤ 7` 且空位为 0 → 状态「已宣发」。

## 4. 结算

`settle()` 主循环里，`item.kind === 'show'` 在 `ACTIONS[item.actionId]` 查表**之前**分支：

- 调 `settleShow(state, item, booking)`，返回新 state + 更新 `bookings` 里对应条为 `done`。
- **不触发**常规事件、剧情事件、任务自动领取（演出是独立事件）。
- 写一条 `kind: 'show'` 日志，文本含各模块金额。
- 时间照常推进到 `item.endAt`。

本轮结算用**简化合并公式**（P2 才拆五模块）：

```
slotMul = [0.8, 1.0, 1.2, 1.4] 按 slot/N 落位（开场/中坚/次压轴/压轴）
门票 = ticketBase × (0.5 + 0.5 × min(1.5, fame / 1000)) × slotMul
特典 = goodsBase × 匹配度 × (0.6 + 0.4 × 0.7)     // 曲目熟练度 P2 接，先按 0.7 常数
属性 = statGain
粉丝 = fanGain
```
- `fame` 本轮用**临时派生**：`run.fans` 总数 / 10 + `party.members.length * 40`，写成 `partyFameStub()` 并标注 `// P2 换成正式组合名气`。
- `匹配度 = Σ(audience[t] × 玩家该类粉丝占比)`，玩家总粉丝为 0 时取 0.5。
- 商务/拍摄（个人通告）：门票与特典合并成「完成收益」一次性给，`slots = 1`。

### 5.3 已参与演出

两段：`待开演`（含已宣发）、`已完成`（可展开看结算明细，逐项列门票/特典/属性/粉丝）。

### 5.4 演出日历

月历，标：已报名日（实心）、开演日（描边）、可报名但未报的日子（浅底）。

### 5.5 报名 / 取消的交互

- 报名成功：**立即**扣排程槽位（写 `kind:'show'` 的 fixed 项）、`entryFee` 入账、日志、`setNotice('报名成功，出场费 ¥X 已到账')`，同步走 `pushWholeState`（**不要**接进 outbox 队列——报名是低频动作，走普通持久化即可）。
- 同一天已有一场 → 顶部提示「这天你已经有安排了」。
- 当天剩余空槽 < `slots` → 「这天行程排满了，先去行程里腾个位置」。
- 取消：`d > 15` 直接退；`7 < d <= 15` 弹确认框写明违约金金额；`d <= 7` 按钮禁用。
- 取消成功后删掉那条 fixed 排程项、追回违约金、状态改 `cancelled`。

### 5.6 必须同时改的三处

1. **安排行程弹窗**：`category === 'performance'` 的行动**全部不显示**（6 个：show/street-live/comic-stage/commercial/one-man/cheki）。`actions` 表不改，只是入口关掉。
