## 本文回答什么

- 哪些东西必须自动化测试？
- 什么算「做完了」？
- 怎么防止改数值改崩、改存档读不出？

## 0. 原则

- **规则逻辑必测**（纯函数，成本低、收益高）
- **UI 少测**（文字游戏 UI 变化快，测了容易白测）
- **存档迁移必测**（最容易被忽略、最容易丢玩家数据）
- **内容校验自动化**（文案 key 缺失靠 CI 拦，不靠人眼）

## 1. 测试分层

| 层 | 测什么 | 工具 | 覆盖目标 |
| --- | --- | --- | --- |
| 单元 | `game/` 下的规则与公式 | Vitest | 核心函数 80%+ |
| 快照 | 30 天数值模拟 | Vitest + 假时钟 | 每次改数值跑一次 |
| 迁移 | vN → vN+1 存档 | Vitest | 每加一版必测 |
| 内容 | 文案 key、事件引用、数值配置 | 自定义脚本 | 100% 引用有效 |
| 手工 | 真机手感、摸鱼场景 | 人 | 每阶段一次 |

## 2. 必须覆盖的关键用例

### 2.1 时间与排程

- [ ] 排程跑完后自动停在静止态
- [ ] 无排程时时间不流逝
- [ ] 触发事件时自动中断
- [ ] 关页面再打开，从停点继续（不补算、不丢失）
- [ ] 排程中途手动停止，已完成部分正确结算

### 2.2 数值与经济

- [ ] 属性不会超过上限
- [ ] 资金不足时不能接付费培训
- [ ] 心情系数极值不导致负数收益
- [ ] 连续 30 天模拟，数值曲线单调、不发散

### 2.3 存档

- [ ] 每个字段写入后能原样读出
- [ ] 老版本存档能迁移到最新
- [ ] 损坏存档不崩溃，能导出原始内容
- [ ] 覆盖存档前生成备份

### 2.4 内容

- [ ] 所有文案 key 都有值
- [ ] 没有未替换的 `{{变量}}`
- [ ] 事件引用的 flag 都存在
- [ ] 数值表字段完整（无 `null`）

## 3. 验收标准（DoD）

一个功能算「完成」，需要同时满足：

- [ ] 行为符合对应文档
- [ ] 有单测或可复现的手工验证步骤
- [ ] 存档结构变化已加迁移
- [ ] 文案已进 key 表
- [ ] 文档同步更新
- [ ] 在窄屏 / 深色模式下不崩

## 4. 数值回归怎么做

```
tests/simulate-30days.test.ts
  → 用假时钟跑 30 天固定策略
  → 输出：属性曲线、资金曲线、事件触发数
  → 断言：不出现 NaN / 负资产 / 属性溢出
  → 快照：与上次结果对比，变化超过阈值时人工确认
```

## 4.5 联机结算测试（联机后必做）

- [ ] 同一份状态 + 同一 `seed`，客户端与服务器算出的分数完全一致
- [ ] 结算函数幂等：同一演出窗口重复演算，结果不变
- [ ] 截止时间后提交被拒绝
- [ ] 未提交的玩家按默认策略参赛，不报错、不判负
- [ ] 输入顺序变化（提交列表打乱）不影响结果
- [ ] 属性被篡改的请求被服务端拒绝

## 5. 发布前检查

- [ ] 生产构建通过（`pnpm build`）
- [ ] 无 console 报错
- [ ] 首屏 < 1 秒（本地静态）
- [ ] 手机与桌面各走一遍完整流程
- [ ] 存档导入导出可用
- [ ] 老板键可用
