## 0. 结论先行

1. **组合数是免费的，部件数是贵的**：3 服装 × 2 发型 × 4 发色 × 饰品 4 槽（各 2 态）= **384 种外观，17 件素材**。前提是画布、锚点、参数表三件事画之前就冻结；之后加第 N 件装备只是加一个 Part，不动底模（§1.5）。
2. **全身 Q 版的显存比 v1 半身写实还低**：1 页 2048 = **16MB**，加舞台服启用第 2 页 1024 → **20MB 封顶**（脚本实测）。Q 版色块大、留白多，这是"做得更可爱但更便宜"的一个例外。
3. **换装走程序侧 part opacity**，不建模型参数（理由见 §2.3）。
4. **发色是正式装备**（haircolor 槽）：每发型每色一组完整上色（2 发型 × 4 色 = 8 组），挑染/渐变直接画在发色贴图里。
5. 总工作量 **47 人日**（熟手单人 6–8 周，含返工 9–11 周）。一身包让单件服装变贵（14 片 vs 上衣 8 片），但删掉了袜/鞋槽与合法性表，净 +2。

## 1. 换装部件系统（对齐装备表 `equipments.json` v2.2）

### 1.0 与装备表的映射（先读这节）

装备表现行 **68 件草稿**，四槽结构：**outfit 30 / hair 12 / haircolor 12 / accessory 14**。美术部件按**装备 ID 一一映射**；"更换的能力"由程序侧 part opacity 切换保证（§2.3），**加第 N 件装备只是加一个 Part，不动底模、不动参数、不动已有部件**（流程见 §1.5）。

| 装备槽 | 美术承载 | 说明 |
|---|---|---|
| `outfit` 服装 | **一身包**：上衣 + 下装 + 袜 + 鞋画在同一个 Part 里 | 不拆上下身；body 常驻皮肤（含裸腿与脚）打底，服装是覆盖层 |
| `hair` 发型 | 7–9 片分层 + 呆毛/马尾物理锚点 | 只承载**形状** |
| `haircolor` 发色 | 每发型每色一组完整上色（共用网格与线稿） | 挑染/渐变效果画在发色里，不再设独立发梢槽 |
| `accessory` 饰品 ×4 | 按部位分 4 槽：**头 / 颈 / 耳 / 腕**，每槽一件可叠戴 | 数据表无子槽字段，程序侧需按部位白名单限制——**需策划确认** |

**一个内容冲突留给策划**：`hair` 槽里"银灰短发"、"白色长直·假发"、"挑染·海盐蓝"三件的名字自带颜色语义，与独立发色槽冲突。建议改名为纯形状（如"短发·狼尾"），或在这三件上锁定发色。

### 1.1 部件表（P0 占位 17 件 → 384 种外观）

| 槽 | 部件 ID（P0 占位） | 内容 | 对应装备 | 件数 |
|---|---|---|---|---|
| 底模 | `body` | 皮肤 + 脸 + 躯干 + 四肢 + **裸腿 + 脚**（常驻，不算换装件） | — | 1 |
| 服装 | `outfit_practice` / `outfit_cardigan` / `outfit_stage` | 素色练习服 / 针织开衫套 / 黑亮片舞台服——**各含袜与鞋** | `eq-plain-practice` / `eq-knit-cardigan` / 新增待补 | 3 |
| 发型 | `hair_short` / `hair_twin` | 齐肩短发 7 片 / 双马尾·右高左低 9 片 | 占位；正式用 `eq-hair-*` 定稿 | 2 |
| 发色 | `haircolor_01..04` × 2 发型 | 自然黑 / 亚麻棕 / 蜂蜜茶 / 深栗色 | `eq-hc-natural-black` / `eq-hc-linen-brown` / `eq-hc-honey-tea` / `eq-hc-chestnut` | 8 |
| 饰品 | `acc_head_catear` / `acc_neck_choker` / `acc_ear_star` / `acc_wrist_band` | 头 / 颈 / 耳 / 腕各 1 件 | `eq-cat-ears` / `eq-velvet-choker` / `eq-star-earrings` / `eq-cheer-band` | 4 |
| 表情 | `exp_01..06` | 默认 / 微困 / 抿嘴笑 / 惊讶 / 不悦 / 紧张 | — | 6 |

**外观总数**：3 服装 × 2 发型 × 4 发色 × 饰品（头2×颈2×耳2×腕2 = 16 态）= **384 种**。
对比 v2.1 的 4,608：不拆分的代价就是组合数（下装/袜/鞋的混搭消失，build 多样性归玩法侧评估）；红利是**零穿帮**、合法性表整张删掉、每件服装观感完整。组合数会随装备扩充继续涨，素材永远按"件"算。

### 1.2 合法性约束：不需要了

v2.1 的两条冲突（袜鞋互斥、长下摆盖袜口）随"一身包"全部消失；饰品按部位分槽天然互斥。**程序侧不需要任何搭配合法性检查**——这是本次改版最大的工程红利。

### 1.3 发色：正式装备，不再是自定义层

- 发色 = 装备（`haircolor` 槽），每件 = 该发型下一组完整上色（共用网格与线稿，只换色）。
- P0 出 4 色（装备表前 4 件）；rare 色（亚麻灰、樱花粉等）随装备扩充按 §1.5 流程增补，1–2 人日/色。
- 挑染、渐变、发梢撞色等效果**画在发色贴图里**，由具体发色装备承载（例：若做"海盐蓝挑染"，它是一件 haircolor 装备，不是叠加层）。
- 发色落在 L 35–60；高饱和色面积 ≤ 4% 画面。

### 1.4 命名规范

```
{组}_{装备id}_{序号}    hair_short_front_01
                        haircolor_eq-hc-natural-black_02
                        outfit_eq-plain-practice_body
                        acc_head_eq-cat-ears_01
                        exp_tired
```

- 组名固定 11 个：`body / face / hair_A / hair_B / haircolor / outfit / acc_head / acc_neck / acc_ear / acc_wrist / exp`
- Part ID 用同名前缀：`Part_hair_A`、`Part_outfit_02`、`Part_acc_head_01`（程序侧按 Part ID 切换）
- 序号两位，不出现中文、空格、大写

### 1.5 扩展契约：加第 N 件装备的流程（"能换"的硬保证）

| 装备类型 | 片数结构 | 人日/件 | 绑定影响 |
|---|---|---|---|
| 服装（一身含鞋袜） | 14 片（前片/后片/袖2/领/下摆/裙裤2/袜2/鞋2/细节1） | 4–5 | 只重排该件自身层级，身体不动 |
| 发型 | 7–9 片 | 4–6 | **唯一例外**：呆毛/马尾锚点要单独绑物理 |
| 发色 | 1 组完整上色（复制对应发型片结构改色相） | 1–2 | 无 |
| 饰品 | 2 片 | 0.5 | 无 |

固定五步：

1. 同画布（2400×3600）、同 10 条锚点线画（锚点见 §4）；
2. 命名 `{组}_{装备id}_{序号}`，建 Part `Part_{组}_{n}`；
3. 片数结构按上表，不许自行增减；
4. 前端加一行映射：装备 ID → Part ID；
5. 验收：三图并排（默认装扮 / 新件单穿 / 新件 × 最不搭的已有件），过 10% 缩略图测试。

**承诺**：底模冻结后，扩充装备不触碰 `01_body` / `02_face` / 参数表 / 物理组。唯一例外是发型（呆毛与马尾锚点每个发型要单独绑）。

**换装不占参数**（见 §2.3）。Q 版**不加腿部 IK 参数**：腿短、且待机不迈步，靠 `ParamBodyAngleZ` + `ParamBodyY` 带动即可，加 IK 是浪费。

> **手部动作替代手法（v2.5，给 B2a 的绑定硬约束）**：本表**没有独立手臂 / 手部参数**。行动动画里所有「抬手 / 挥手 / 递物 / 擦桌 / 摆臂」不得真动手臂，一律由 `ParamBodyAngleZ`（±3–8°）+ `ParamBodyY` 升降带出，并靠头部朝向 / 视线与 7 组物理补位。**手臂与小圆手 ArtMesh 必须挂到 `ParamBodyAngleZ` 驱动的同一变形器上（关节重叠区 10–15%），不新建参数**；否则 24 段动作做不出来，或被迫改参数表导致连锁重调。`ParamBodyAngleX` 范围仅 −10..10，只能做「侧身 ≤8°」，不能做转身。详见规划表 §1.1。

### 2.3 换装怎么实现：走程序侧

| 做法 | 代价 | 结论 |
|---|---|---|
| 模型内参数驱动（`ParamSwitchHair` 0..4 + opacity 阶梯） | 5 槽 = +5 参数 × 每部件 3 段关键帧，Cubism 里极易做错，导出后难调试 | ❌ |
| **程序侧 part opacity（推荐）** | 前端一行：`coreModel.setPartOpacityById('Part_hair_A', 0/1)` | ✅ |

- 每个可选部件是一个独立 Part，互斥组内同一时刻只有 1 个 opacity = 1。
- 切换时必须补 **0.3s 的 `switch_pose`**（遮罩 + 惯性），否则会看到"两个发型叠在一起"的 1 帧。
- 保底：若实测有闪烁，退化为"两套完整模型交叉淡入"，代价是显存翻倍（需重评 §3）。

|---|---|---|---|---|
| 前发 | ±7° | 0.12 | 0.55 | 跟随 `ParamAngleX` 延迟 0.08s |
| 侧发 | ±5° | 0.15 | 0.60 | |

### 2.5 动作清单（无交互，靠这几组撑"活着"）

| 动作 | 时长 | 循环 | 内容 | 随机化 | 触发 |
|---|---|---|---|---|---|
| `idle_normal` | 8.0s | 是 | 呼吸 ×2、**重心左右晃 1 个来回**、眨眼 ×2–3、视线游移 ×1 | 眨眼 2.8–5.4s / 视线 6–14s / 晃动幅度 ±1.5px | 常驻 |
| `idle_tired` | 10.0s | 是 | 头低 5°、闭眼 0.45s（正常 0.12s）、呼吸振幅 ×0.7、**呆毛塌 15°** | 区间拉长 1.5 倍 | 体力 < 30% |
| `idle_stage` | 6.0s | 是 | 头抬 3°、**踮脚 1 次（ParamBodyY +0.08）**、马尾振幅 ×1.6、嘴微张 | — | 演出事件 |
| `switch_pose` | 0.3s | 否 | 遮罩淡入 0.12s → 部件切换 → 头发/马尾惯性回弹 | — | 换装 |
| `exp_01..06` | 0.15s | — | 表情混合（Expression，不占动作槽） | — | 事件 |

**Q 版最划算的一笔：重心左右晃。** 一个参数 + 物理跟随，就能让"站着的大头女孩"从"贴纸"变成"活着"。成本约半天，收益远超任何加特效的方案。**必须做。**

**为什么必须随机化**：固定 8 秒循环，玩家 30 秒内就识破"这是 GIF"。眨眼、视线、晃动三个变量各自独立随机，是"活的"和"循环的"之间唯一的差别。

> **范围澄清（v2.4）**：本节动作清单仅指**常驻循环动作**（idle / 过渡 / 表情混合）。用户 2026-11-03 提出的「每个行动触发 2–5 秒、2–3 段随机播放的动画」是**另一层（行动动画）**，不在此表内，工序判断与成本见 [动作动画方案与成本估算](idollife-动作动画方案与成本估算.md)。两层共用同一套 25 参数 / 7 物理，**不重复建参数、不重复绑定**。

## 3. 纹理与显存预算

### 3.1 口径

Web 端**不能压纹理**（浏览器不支持 ASTC/ETC2，解码后就是 RGBA32），显存 = 宽 × 高 × 4 字节，没有折扣。`asset_budget.py` 实测（Q 版全身方案）：

| 方案 | 纹理 | 显存 | 适用 |
|---|---|---|---|
| **P0** | 1×2048² | **16.00 MB** | 全身 + 2 发型 × 4 色 + 3 服装（一身含鞋袜）+ 4 饰品 |
| P1（加舞台服/季节款） | 1×2048² + 1×1024² | **20.00 MB** | 脚本输出：16.00 + 4.00 = 20.00 MB，预算 96MB，余量 76MB ✅ |

> **比 v1 省的原因**：Q 版是平涂纯色块，几乎没有渐变与纹理细节，PNG 量化后色阶也不掉；同样 2048² 能装的部件数比写实风多约 1.6 倍。

### 3.2 图集策略

- 换装部件**全部常驻图集**（不做运行时换贴图）→ 推高图集的是"部件总数"，不是"组合数"。
- 分页：第 1 页放"永远在场"的（脸、身体、默认发与衣），第 2 页放可选件。
- **禁止 4096² 单页**：集显与移动端 Safari 都可能直接失败。
