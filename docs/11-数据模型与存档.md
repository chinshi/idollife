## 0. 三层存储

| 层 | 内容 | 存哪 | 生命周期 |
| --- | --- | --- | --- |
| **Meta** | 跨周目：解锁、结局图鉴、纪念品 | 服务端 + 本地缓存 | 永久 |
| **Run** | 单局：角色、粉丝、排程、日志 | 本地为主 + 服务端快照 | 一个周目 |
| **Server** | 账号、排程、动作日志、演出窗口 | 服务端 | 永久 |

> **为什么分三层**：单局数据要能离线跑（本地），但校验与联机必须有服务端副本（Server 层）；周目结束后单局丢弃，只留 Meta。

## 1. 核心状态树

```ts
type Tier = 'low' | 'mid' | 'high';

/** 跨周目存档 */
interface MetaSave {
  version: number;
  unlocks: string[];     // 解锁的模板 / 事件 / 出身
  endings: string[];     // 已见结局 id
  souvenirs: string[];   // 纪念品（微量加成）
}

/** 单局根存档 */
interface RunSave {
  version: number;
  runId: string;
  startedAt: number;
  lastSyncAt: number;      // 最后与服务端同步的时刻
  stage: 'trainee' | 'debut' | 'regular' | 'popular';
  idol: Idol;
  party: Party;
  fans: Fans;
  axes: { self: Tier; others: Tier; fit: Tier };
  inventory: Inventory;
  schedule: ScheduleItem[];
  flags: Record<string, boolean | number>;
  log: LogEntry[];
  settings: Settings;
}
```

## 5. 物品与装备

```ts
interface Inventory {
  money: number;
  items: Item[];
  equipped: Partial<Record<EquipSlot, string>>;
}

type EquipSlot = 'outfit' | 'hair' | 'makeup' | 'acc1' | 'acc2' | 'acc3' | 'acc4';

interface Item {
  id: string;
  kind: 'equip' | 'consumable';
  slot?: EquipSlot;
  rarity?: 'common' | 'rare' | 'legendary';
  affixes: Affix[];        // 最多 4 条
}

type Affix =
  | { type: 'stat'; key: 'vocal' | 'dance' | 'acting' | 'talk'; value: number }
  | { type: 'affinity'; key: FanType; value: number }      // 百分比
  | { type: 'proficiency'; key: 'stage' | 'song' | 'dance'; value: number }
  | { type: 'special'; id: string };
```

## 6. 排程（关键）

```ts
interface ScheduleItem {
  actionId: string;
  startAt: number;         // 真实时间戳
  endAt: number;
  withMemberId?: string;   // 邀请同行

```

**排程必须上传服务端**——服务器靠它重放离线期间发生的事（见 [12 §3](12-番茄钟与时间系统.md)）。

## 7. 服务端表

| 表 | 关键字段 | 作用 |
| --- | --- | --- |
| `users` | id, email, created_at | 账号 |
| `idollife_runs` | run_id, state(jsonb), schedule(jsonb), revision, last_sync_at | 单局快照 |
| `schedules` | run_id, items_json, updated_at | 排程队列 |
| `actions` | run_id, seq, type, payload, created_at | 动作日志（重放用） |
| `show_windows` | id, game_week, open_at, lock_at, settle_at | 演出窗口 |
| `entries` | window_id, user_id, config_json, submitted_at | 报名单 |
| `results` | window_id, user_id, grade, contribution, report, rewards | 结算结果 |

## 8. 同步协议（草案）

```
客户端 → POST /v1/idollife/sync
  { runId, clientSeq, scheduleHash, actions: [...] }

服务器 → 200
  { revision, lastSyncAt, accepted: [...], rejected: [...], state?: {...} }
```

- **幂等**：每次带 `clientSeq`，重复提交不重复记账
- **服务器重放**：按 `lastSyncAt` + 排程，算出本该发生什么
- **冲突**：以服务器为准，客户端回滚到 `revision`

## 9. 校验点（与 09 §4.2 对齐）

| 校验 | 时机 | 规则 |
| --- | --- | --- |
| 时间戳 | 每次同步 | 不得倒流 |
| 速率 | 每次同步 | 每现实分钟最多 N 个行动 |
| 收益上限 | 行动完成 | 单次收益 ≤ 理论上限 |
| 快照跳变 | 同步 | 数值跳变过大 → 要求重放 |

## 10. 体积与迁移

| 项 | 大小 |
| --- | --- |
| RunSave（不含日志） | < 10 KB |
| 日志（保留 500 条） | ~ 50 KB |
| 服务端单局 | < 200 KB |

迁移规则：

- `version` 只增不减
- 每次改结构加一条迁移函数 + 测试
- 服务端与本地同时保留旧版本读取能力
