# 21 · 时间轴渲染与动画踩坑记录

> 记录 2026-11-01 调试「时间轴残影」的完整过程。移植到别的技术栈（移动端 / Unity / 小程序 / 桌面端）时，
> 请优先读 **§5 检查清单**。

---

## 1. 现象

时间轴（竖向、随游戏时间滚动）在**推进**时出现拖影：
文字像叠了两层淡淡的残像，向上移动时尤为明显。

后期发现：**即使不推进、刷新页面后，静止状态也有重影**。
这一点把问题从「动画」彻底转向了「渲染」。

---

## 2. 试过的方案（全部失败）

| # | 方案 | 结果 | 为什么没用 |
|---|---|---|---|
| 1 | `overflow: auto` + `scrollTo` 手算居中 | 滚动位置不准 | 嵌套滚动容器 + 动态行高，`getBoundingClientRect` 差值算错 |
| 2 | 引入 `scroll-into-view-if-needed` | 居中对了，仍有残影 | 库解决的是"滚到哪"，不是"怎么画" |
| 3 | 容器 `overflow: hidden` + 内层 `translateY` 整体位移 | 仍抖 / 残影 | 位移值来自"每行 offsetTop"，行动完成时行布局变化 → 位移跳变 |
| 4 | 改成「按时间映射坐标」：`top = 50% + (startAt − now) × px/ms` | 位置对了，残影还在 | 每行每 100ms 各自改 `top` → **每行独立重排重绘** |
| 5 | 去掉 `will-change` / `transition` | 无改善 | 不是过渡动画造成的 |
| 6 | 单层 `track` + 只平移外层 | 无改善 | 只是减少重绘次数，**亚像素问题依旧** |
| 7 | `translate3d` + `Math.round(位移)` | 无改善 | 只把**外层**取整了，**行内部坐标仍是小数** |

---

## 3. 真正的根因（三个叠加）

### 3.1 亚像素坐标（主因，静止也模糊）

时间轴像素比例是「一条行动 = 56px」，于是：

```
pxPerMs = 56 / 60000 ≈ 0.000933
某行 top = (行动开始 − 基准) × 0.000933 = 31.36px   ← 小数
容器 527px 的 50% = 263.5px                        ← 半点
```

文字画在小数像素上，浏览器必须做**半像素抗锯齿 / 重栅格化**，
看起来就是「发虚、叠了两层的重影」。

> 关键判据：**静止时也有残影 → 一定是坐标问题，不是动画问题。**

### 3.2 每帧逐行重绘

每 100ms 每行改一次 `top` → 触发布局 + 重绘，
十几行同时重算，合成器跟不上，移动时产生拖尾。

### 3.3 合成层副作用

给每行加 `will-change: transform` 后，元素被提升为独立合成层；
状态切换（加「已完成」标签、改背景色）时容易残留上一帧画面。

---

## 4. 最终方案：不做连续运动

既然游戏节奏本来就是「一条行动 = 一段时间」，**中间过程没有信息量**，
索性放弃连续滚动：

- 行的位置只由 `run.at`（已完成的进度）决定 → **一条行动期间完全静止**
- 只有行动完成时才整体跳一格（56px）
- 所有坐标 `Math.round` 取整
- 容器高度用 `ResizeObserver` 实测，不用 `50%`

```tsx
// 轨道位移：整数像素
transform: translate3d(0, ${Math.round(boxH / 2 + (baseTime - run.at) * pxPerMs)}px, 0)

// 每一行
top:      ${Math.round((it.startAt - baseTime) * pxPerMs)}px
height:   ${Math.round((it.endAt - it.startAt) * pxPerMs)}px
```

倒计时文字仍然实时刷新（只改文字，不改布局）。

## 5. 移植检查清单

如果将来用别的技术栈重做，逐条对照：

### 坐标
- [ ] 所有布局坐标**取整到整数像素**（含容器尺寸的 50%、缩放后的位置）
- [ ] 避免 `50%` + `translateY(-50%)` 这类可能产生 `.5` 的写法；改用实测高度
- [ ] 缩放（DPR / 适配）后重新取整，不要只在 CSS 层取整

### 性能
- [ ] 一帧只改**一个**位移值（单层平移），不要让每行各自改 `top`
- [ ] 位移优先用 `transform`，不要用 `top/left`
- [ ] 避免对大量元素设置 `will-change`
- [ ] 更新频率别超过 30fps；只有文字需要高频刷新时，把文字和布局**分开更新**

### 设计
- [ ] 动画是否有必要？**离散跳变**往往更稳、更符合"一步一条行动"的节奏
- [ ] 如果确实需要连续滚动，先确认能否用原生 `scroll` / 平台自带列表组件（它们处理了合成与取整）

### 验证方法
- [ ] 静止截图放大 200% 看文字边缘是否有重影
- [ ] 慢速滚动录屏逐帧检查拖尾
- [ ] 在不同 DPR（100% / 125% / 150% 缩放）下都测一遍 —— **Windows 125% 缩放最容易暴露**

## 7. 一句话总结

> **「静止也有残影」= 坐标没取整。**
> **动画不是靠加特效解决的，而是先问：这段动画有没有必要存在。**
