## 0. 一条铁律

**游戏规则是纯函数：不依赖 React、不依赖 `Date.now()`、不依赖 `localStorage`、不依赖随机数。**

```ts
settle(state, schedule, from, to, seed) => { state, events }
```

好处：

- 规则可以单测，不需要浏览器
- **客户端与服务器跑同一份代码** → 天然可校验
- 可以喂假时间模拟 30 天，做平衡性验证

## 1. 分层

| 层 | 职责 | 允许依赖 | 禁止 |
| --- | --- | --- | --- |
| `content` | 文案、数值表、事件数据 | — | 任何逻辑 |
| `core` | 规则、结算、时间推进（纯函数） | `content` | DOM、时钟、存储、`Math.random` |
| `client` | store、存档、UI、本地预测 | `core`、`content` | 写业务规则 |
| `server` | 账号、排程存储、重放、联机结算 | `core`、`content` | 写业务规则 |

数据流：

```
用户操作 → client 调 core 本地结算（乐观） → 上报 server
                                              ↓
                                    server 用同一份 core 重放
                                              ↓
                                   返回 revision，冲突则回滚
```

## 2. Monorepo 布局

```
idollife/
├─ docs/                  # 设计文档（本目录）
├─ packages/
│  ├─ core/               # ★ 共享：规则、结算、类型
│  │  ├─ src/
│  │  │  ├─ settle.ts     # 主结算入口
│  │  │  ├─ systems/      # 属性、粉丝、事件、演出
│  │  │  ├─ rules/        # 条件、公式、随机（种子）
│  │  │  └─ types.ts
│  │  └─ tests/
│  ├─ client/             # Vite + React
│  │  ├─ src/
│  │  │  ├─ app/          # 外壳、路由、快捷键、老板键
│  │  │  ├─ state/        # store、存档、同步
│  │  │  ├─ ui/           # screens / components
│  │  │  └─ content/      # 文案与数值配置
│  │  └─ index.html
│  └─ server/             # Hono / Workers
│     ├─ src/
│     │  ├─ routes/       # auth / sync / shows
│     │  ├─ jobs/         # 定时结算
│     │  └─ db/           # schema 与查询
│     └─ tests/
├─ package.json           # workspace
└─ pnpm-workspace.yaml
```

> `core` 里出现 `import 'react'` 或 `Date.now()` 就是违规——用 eslint 规则挡住。

## 3. 时间推进的边界

```ts
// core 只认「从什么时候到什么时候」，不认"现在"
settle(run: RunSave, schedule: ScheduleItem[], from: number, to: number, seed: string)
```

- 时间戳由调用方给：客户端给本地时钟，服务器给自己的时钟
- 排程耗尽后，`to` 之后的时段不产生收益
- 同一份输入 + 同一 `seed` → 必然同一结果

## 4. 同步与冲突

| 情况 | 处理 |
| --- | --- |
| 客户端本地先算 | 乐观显示，标「待同步」 |
| 服务器重放结果不同 | 以服务器为准，回滚到 `revision` |
| 重复提交 | 按 `clientSeq` 幂等丢弃 |
| 离线累计太久 | 服务器按排程上限重放，超出部分作废 |

## 5. 加一个新系统的最小改动

以「粉丝系统」为例：

- [ ] `content/balance/fans.json` 数值配置
- [ ] `core/systems/fans.ts` 纯函数（增长、转化、衰减）
- [ ] `core/settle.ts` 接入结算流程
- [ ] `core/types.ts` + `client/state` 存档字段（含迁移）
- [ ] `client/ui` 展示
- [ ] `core/tests` 规则用例
- [ ] 文档：更新 03 / 04 / 11 / 20

> 超过 5 个文件说明抽象有问题——先重构再加。

## 6. 错误处理

| 情况 | 策略 |
| --- | --- |
| 存档损坏 / 版本不认识 | 不崩溃，提示并提供「新游戏」，备份原档 |
| 数值溢出 / NaN | `core` 出口做 clamp 与断言 |
| 配置缺失 | 构建期 Zod 校验拦截 |
| 服务器时钟与本地差异过大 | 以服务器为准，提示「进度已校准」 |
| 断网 | 本地继续跑，重连后同步；冲突回滚 |
