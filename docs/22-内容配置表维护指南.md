## 2. 各表字段说明

### actions.json（行为表）

定义「能做什么」，不含具体收益。

```jsonc
{
  "id": "vocal-karaoke",
  "name": "唱 K",
  "category": "growth",          // 分类字段名
  "categoryName": "提升属性",     // 分类中文名
  "displayCondition": {},        // 显示条件（空=一直显示），写法同事件触发条件
  "times": 0,                    // 可执行次数，0=无限制
  "timesScope": "run",           // 次数范围：run 整局 / week 每周 / day 每天
  "affectedStats": ["vocal"],    // 影响的属性（可多个）
  "durationMinutes": 1           // 单次行动流逝几分钟
}
```

### action_results.json（行为结果表）

同一个行为在不同条件下可以有不同收益和文案，通过 `actionId` 关联。

```jsonc
{
  "id": "res-vocal-tired",
  "actionId": "vocal-karaoke",
  "actionName": "唱 K",
  "condition": { "staminaBelow": 30 },   // 空 = 默认结果
  "priority": 10,                        // 小的先匹配
  "effects": {
    "stamina": -10,
    "money": -50,
    "stats": { "vocal": [1, 1] }         // 数字或 [最小值,最大值]
  },
  "text": "嗓子有点哑……（演唱 +{vocal}）"
}
```

规则：

1. 执行时按 `priority` 从小到大找**第一条条件匹配**的结果
2. 每个行为**必须有一条默认结果**（`condition` 为空），校验会检查
3. 文案占位符：`{属性字段名}`、`{n}`（第一个属性）、`{stamina}`、`{money}`
4. 界面预览用默认结果，实际执行按条件取
### events.json

**常规事件（routine）**：不暂停时间，只改数值

```jsonc
{ "id": "r-rain", "text": "下雨了…", "stamina": -1, "stat": "talk", "gain": 1 }
```

**剧情事件（story）**：`major: true` 会**暂停时间**，其余进队列不打断

```jsonc
{
  "id": "first-audition",
  "title": "一个试镜机会",
  "major": true,
  "text": "……",
  "requires": { "statsAtLeast": { "dance": 15 }, "flagsNot": ["ev:first-audition"] },
  "choices": [
    {
      "id": "go",
      "label": "去",
      "text": "你去了……",
      "effects": { "stamina": -10, "axes": { "self": 8 }, "stats": { "dance": 2 } },
      "setFlag": "first-audition"
    }
  ]
}
```

**触发条件 DSL**（`requires`，全部可省略，多个条件是与关系）：

| 字段 | 含义 | 例子 |
| --- | --- | --- |
| `statsAtLeast` | 属性不低于 | `{ "dance": 15 }` |
| `axesAtLeast` | 三轴不低于 | `{ "others": 45 }` |
| `axesBelow` | 三轴低于 | `{ "fit": 34 }` |
| `staminaBelow` | 体力低于 | `20` |
| `fansAtLeast` | 某类粉丝不少于 | `{ "stage": 50 }` |
| `flagsNot` | 这些标记不存在才触发 | `["ev:first-audition"]` |


### attributes.json

| 列 | 含义 | 取值 |
| --- | --- | --- |
| `category` | 属性分类**字段名** | `visible` / `hidden` / `status` / `fans` |
| `categoryName` | 属性分类**中文名** | 显性属性 / 隐藏属性 / 状态 / 粉丝属性 |
| `name` | 属性名称（界面显示） | 演唱、舞蹈… |
| `key` | 属性字段名（代码里用） | vocal、dance、acting、talk、self、others、fit… |
| `hidden` | 是否隐藏 | true / false |
| `linked` | 关联属性（显示方式） | **0=完全隐藏，1=完全可见，2=隐藏仅占卜可见** |

当前内容：4 个显性属性、3 个隐藏属性、体力、6 类粉丝属性。

界面上的属性名（`STAT_LABEL`）现在**由这张表生成**，改 `name` 就改显示。

## 3. 日常维护流程

```powershell
# 1. 改 JSON
#    建议用 VS Code 打开 packages/core/data/

# 2. 校验（语法 + 字段完整性 + id 唯一）
pnpm check:data

# 3. 本地看效果
pnpm --filter @idollife/server start     # 终端 A
pnpm dev                                 # 终端 B → http://127.0.0.1:5273

# 4. 确认没问题再推线上（push 后 Vercel 自动部署）
git add -A
git commit -m "content: 调整 xxx"
git push
```

> `pnpm test` 已经包含 `check:data`，所以构建前跑一次测试就能挡住坏数据。

## 4. 维护建议（按投入从低到高）

| 方案 | 成本 | 适合 |
| --- | --- | --- |
| **JSON + 校验脚本**（现在这样） | 零 | 你自己改，字段不多 |
| **VS Code 挂 JSON Schema** | 低 | 编辑时实时提示字段、枚举值 |
| **表格工具**（Excel / 飞书表格导出 JSON） | 中 | 文案量大、要多人协作 |
| **自建内容后台**（读表 + 表单编辑 + 一键发布） | 高 | 有运营同学参与时 |

建议顺序：先用现在的 JSON，等**事件超过 50 条**或**有第二个人要改内容**时，再考虑表格/后台。

---

## 5. 加新内容的最小步骤

**加一个行动**：在 `actions.json` 里加一条（id 唯一）→ `pnpm check:data` → 界面自动出现。

**加一个剧情事件**：在 `events.json` 的 `story` 里加一条，写清 `requires` 和 `choices` → 校验 → 触发条件满足时自动出现。

**加一个结局**：在 `endings.json` 里加一条，并在 `endings.ts` 的判定映射里挂上（映射目前仍是代码，因为它是判定逻辑不是内容）。

---

## 6. 注意

- JSON **不能写注释**（`_说明` 字段是给看的，不是注释语法）
- 所有 `id` 必须唯一且**不要随便改**——存档里记的是 id
- 文案里的 `{n}`、`{name}` 是占位符，别删

## 7. 用 Excel 维护（推荐）

每张表**一个独立的 xlsx**，放在 `content/` 下：

```powershell
pnpm content:template     # 从当前 JSON 生成 9 个 xlsx
# 用 Excel 改对应的文件
pnpm content:import       # 导回 JSON（缺文件会跳过并提示），自动校验
```

| 文件 | 对应 | 主要列 |
| --- | --- | --- |
| `attributes.xlsx` | 属性表 | 属性分类 / 分类字段名 / 属性名称 / 属性字段名 / 是否隐藏 / 关联属性 |
| `actions.xlsx` | 行动表 | id / name / category / stat / stamina / gainMin / gainMax / cost / money / text |
| `events.xlsx` | 事件表（3 个工作表） | routine：id/text/stamina/stat/gain；story：id/title/major/text/requires；choices：eventId/id/label/text/… |
| `endings.xlsx` | 结局 | id / title / group / text |
| `shop.xlsx` | 装备 | kind(common/rare) / name / stat / value |
| `members.xlsx` | NPC 池 | type(name/bias) / value |
| `balance.xlsx` | 全局数值 | key / value |
| `characters.xlsx` | 主角模板 | id / name / desc / money / stamina |
| `logs.xlsx` | 日志文案 | key / text |

注意事项：

- **不要改工作表名字**（`events.xlsx` 里固定是 routine / story / choices）
- **不要改表头行**，列顺序也不要动
- `story.requires` 是 JSON 字符串，格式见第 2 节
- 空行会被忽略；`id` / `key` 仍然必须唯一
- 只改某一张表时，其它 xlsx 可以不用管（导入时会跳过不存在的文件）
- 导入后自动跑校验，报错说明表格里有问题

> 已用「模板 → 导入」做过往返验证，内容与原始 JSON 一致。

## 8. 命名约定：枚举字段一律「双名」

除了纯数值字段，所有配置表的枚举/代号字段都要**成对出现**：

| 字段名（代码用） | 中文名（显示用） | 出现在 |
| --- | --- | --- |
| `category` | `categoryName` | actions、attributes |
| `stat` | `statName` | actions、routine、shop |
| `group` | `groupName` | endings |
| `biases` | `biasNames` | members |
| `key` | `name` | attributes（属性字段名 / 属性中文名） |

校验脚本会检查这些成对字段，缺中文名会直接报错。

Excel 里同样是两列并排，例如 `actions.xlsx`：

```
id | name | category | categoryName | stat | statName | stamina | ...
```
