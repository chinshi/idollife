## 2. 各表字段说明

### actions.json

```jsonc
{
  "id": "vocal-karaoke",     // 唯一 id，代码里用它
  "name": "唱 K",             // 界面显示名
  "category": "growth",      // growth 提升属性 / recover 恢复 / work 赚钱
  "stat": "vocal",           // 影响哪个属性（可选）
  "stamina": -10,            // 体力变化，负数为消耗
  "gain": [1, 3],            // 属性成长区间 [最小, 最大]
  "cost": 50,                // 花钱（可选）
  "money": 320,              // 赚钱（可选）
  "text": "……（演唱 +{n}）"  // 日志文案，{n} 会被替换成实际成长值
}
```

### events.json

**常规事件（routine）**：不暂停时间，只改数值

```jsonc
{ "id": "r-rain", "text": "下雨了…", "stamina": -1, "stat": "talk", "gain": 1 }
```

**剧情事件（story）**：`major: true` 会**暂停时间**，其余进队列不打断

```jsonc
{
  "id": "first-audition",
  "title": "一个试镜机会",
  "major": true,
  "text": "……",
  "requires": { "statsAtLeast": { "dance": 15 }, "flagsNot": ["ev:first-audition"] },
  "choices": [
    {
      "id": "go",
      "label": "去",
      "text": "你去了……",
      "effects": { "stamina": -10, "axes": { "self": 8 }, "stats": { "dance": 2 } },
      "setFlag": "first-audition"
    }
  ]
}
```

**触发条件 DSL**（`requires`，全部可省略，多个条件是与关系）：

| 字段 | 含义 | 例子 |
| --- | --- | --- |
| `statsAtLeast` | 属性不低于 | `{ "dance": 15 }` |
| `axesAtLeast` | 三轴不低于 | `{ "others": 45 }` |
| `axesBelow` | 三轴低于 | `{ "fit": 34 }` |
| `staminaBelow` | 体力低于 | `20` |
| `fansAtLeast` | 某类粉丝不少于 | `{ "stage": 50 }` |
| `flagsNot` | 这些标记不存在才触发 | `["ev:first-audition"]` |

### balance.json

| 字段 | 含义 | 当前值 |
| --- | --- | --- |
| `actionMinutes` | 一个行动流逝几分钟 | 1（测试用，正式值改 10） |
| `dailySlots` | 每天行动位 | 3 |
| `showSlots` | 一场演出占几个行动位 | 3 |

| `runDays` | 一周目天数 | 730 |
| `divinationBase` | 占卜基础价 | 100 |

## 3. 日常维护流程

```powershell
# 1. 改 JSON
#    建议用 VS Code 打开 packages/core/data/

# 2. 校验（语法 + 字段完整性 + id 唯一）
pnpm check:data

# 3. 本地看效果
pnpm --filter @idollife/server start     # 终端 A
pnpm dev                                 # 终端 B → http://127.0.0.1:5273

# 4. 确认没问题再推线上（push 后 Vercel 自动部署）
git add -A
git commit -m "content: 调整 xxx"
git push
```

> `pnpm test` 已经包含 `check:data`，所以构建前跑一次测试就能挡住坏数据。

## 4. 维护建议（按投入从低到高）

| 方案 | 成本 | 适合 |
| --- | --- | --- |
| **JSON + 校验脚本**（现在这样） | 零 | 你自己改，字段不多 |
| **VS Code 挂 JSON Schema** | 低 | 编辑时实时提示字段、枚举值 |
| **表格工具**（Excel / 飞书表格导出 JSON） | 中 | 文案量大、要多人协作 |
| **自建内容后台**（读表 + 表单编辑 + 一键发布） | 高 | 有运营同学参与时 |

建议顺序：先用现在的 JSON，等**事件超过 50 条**或**有第二个人要改内容**时，再考虑表格/后台。

---

## 5. 加新内容的最小步骤

**加一个行动**：在 `actions.json` 里加一条（id 唯一）→ `pnpm check:data` → 界面自动出现。

**加一个剧情事件**：在 `events.json` 的 `story` 里加一条，写清 `requires` 和 `choices` → 校验 → 触发条件满足时自动出现。

**加一个结局**：在 `endings.json` 里加一条，并在 `endings.ts` 的判定映射里挂上（映射目前仍是代码，因为它是判定逻辑不是内容）。

---

## 6. 注意

- JSON **不能写注释**（`_说明` 字段是给看的，不是注释语法）
- 所有 `id` 必须唯一且**不要随便改**——存档里记的是 id
- 文案里的 `{n}`、`{name}` 是占位符，别删

---

## 7. 用 Excel 维护（推荐）

不想手动改 JSON 的话，用表格维护再导入：

```powershell
pnpm content:template     # 第一次：生成 content/content.xlsx
# 用 Excel 打开 content/content.xlsx 编辑
pnpm content:import       # 导回 JSON（并自动校验）
```

`content.xlsx` 有 9 张表：

| 工作表 | 对应 | 主要列 |
| --- | --- | --- |
| `actions` | 行动表 | id / name / category / stat / stamina / gainMin / gainMax / cost / money / text |
| `routine` | 常规事件 | id / text / stamina / stat / gain |
| `story` | 剧情事件 | id / title / major / text / requires(JSON) |
| `choices` | 剧情选项 | eventId / id / label / text / stamina / self / others / fit / vocal / dance / acting / talk / setFlag |
| `endings` | 结局 | id / title / group / text |
| `shop` | 装备 | kind(common/rare) / name / stat / value |
| `members` | NPC 池 | type(name/bias) / value |
| `balance` | 全局数值 | key / value |
| `characters` | 主角模板 | id / name / desc / money / stamina |

注意事项：

- **不要改工作表名字**，导入脚本按名字取表
- **不要改第一行表头**，列顺序可以不动
- `story.requires` 这一列是 JSON 字符串，格式见第 2 节
- 空行会被忽略；`id` 仍然必须唯一
- 导入完成后会自动跑一次校验，报错就说明表格里有问题

> 已经验证过：模板 → 导入 → 与原始 JSON **内容完全一致**，可以放心用表格当唯一数据源。
