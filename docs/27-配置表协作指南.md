# 27 · 配置表说明（含项目说明）

> 给「写内容的人」看的操作手册。
> 目标：只改 `content/*.xlsx`，不碰代码，也能安全、可验证地把内容写进游戏。

---

## 1. 项目是什么

**idollife** 是一个纯文字网页养成游戏：你带一个想当偶像的女孩，从素人练到出道/退圈，半年内走到一个结局。

| 项 | 说明 |
| --- | --- |
| 形态 | 纯文字网页（无美术），登录后云存档 |
| 节奏 | 慢节奏，一次行动 = 游戏内 1 天 3 个时段之一 |
| 核心循环 | 练属性 → 赚钱 → 演出/社交 → 提升粉丝 → 解锁事件 → 走向结局 |
| 技术栈 | pnpm workspace：`packages/core`（纯逻辑）/ `packages/client`（React）/ `packages/server`（Hono） |
| 存档 | Supabase（表前缀 `idollife_`，与其它项目隔离） |
| 内容来源 | `content/*.xlsx` → 导入 `packages/core/data/*.json` → 打包进前后端 |

### 1.1 数据流（必须理解）

```
content/*.xlsx          Excel：唯一该改的东西
      │  pnpm content:import
      ▼
packages/core/data/*.json   JSON：程序读的格式（英文键）
      │  构建时 import
      ▼
前端 JS / 服务端 bundle     运行时只看这个
```

**关键点**：

1. 运行时**不读 Excel、不读文件**，内容已经编译进包
2. 客户端算完，服务端用**同一份内容**重放校验 → 内容版本必须一致
3. 所以：**改内容 = 改 Excel + 导入 + 重新构建发布**

## 2. 三条铁律

| # | 铁律 | 违反的后果 |
| --- | --- | --- |
| 1 | **不改表头文字、不插列、不删列、不调列顺序** | 导入按列位置读取，整体错位，静默出错 |
| 2 | **一次只改自己负责的那张表（文件）** | 多人同时改同一文件会互相覆盖 |
| 3 | **改完必须跑 `pnpm content:import` + `pnpm check:data`** | 未导入 = 游戏里看不到；校验不过 = 发版失败 |

补充：

- 不要手改 `packages/core/data/*.json`（除非明确要求），否则下次导入会被覆盖
- 不要改 `scripts/` 下的导入脚本
- id 一经使用**不要改名**（存档、标记、日志都引用它）

## 3. 环境与命令

```powershell
pnpm install                     # 首次
pnpm content:template            # 从 JSON 重新生成全部 Excel（会覆盖！改前先备份）
pnpm content:import              # Excel → JSON（只处理比 JSON 新的表）
pnpm check:data                  # 校验 13 张表结构
pnpm --filter @idollife/core test   # 核心逻辑测试
pnpm dev                         # 起本地（客户端 5273 / API 8787）
```

> `content:import` 会跳过「被 Excel 打开」的文件，并提示 `skip`。**导入前请关闭 Excel。**

### 3.1 标准工作流

```powershell
# 1. 打开要改的 xlsx（其它表别动）
# 2. 改完保存 → 关闭 Excel
pnpm content:import
pnpm check:data
# 3. 本地开 http://127.0.0.1:5273 看效果
```

## 5. 逐表说明

### 5.1 attributes（属性字典）

| 列 | 含义 | 取值 |
| --- | --- | --- |
| 属性分类 | 大类名 | 固有属性 / 显性属性 / 状态 / 性格 / 负向 / 熟练度 / 隐藏属性 / 粉丝属性 |
| 分类字段名 | 大类英文名 | `innate` `visible` `status` `trait` `negative` `proficient` `hidden` `fans` |
| 属性名称 | 中文名 | 演唱、体力、自我… |
| 属性字段名 | 代码字段 | `vocal` `dance` `acting` `talk` `stamina` `mood` `satiety` `self` `others` `fit` … |
| 是否隐藏 | 是否默认隐藏 | TRUE / 空 |
| 关联属性 | 可见性 | 0=完全隐藏，1=显示，2=仅占卜可见 |

> ⚠️ `属性字段名` 是**代码直接访问的键**，不能乱改。新增属性需要同时改代码，这里只负责名称与分类。

### 5.2 actions（行为表）

| 列 | 含义 | 示例 |
| --- | --- | --- |
| id | 行为 ID（唯一） | `vocal-karaoke` |
| 行为名称 | 显示名 | 唱K |
| 行为分类 | 中文分类 | 提升属性 / 赚钱 / 恢复状态 / 演出 |
| 分类字段名 | 英文分类 | `growth` / `work` / `recover` / `performance` |
| 显示条件 | **表达式**，空=一直显示 | `total >= 60` |
| 次数 | 每个周期可做几次，0=无限 | `1` |
| 次数范围 | 计数周期 | `day` / `week` / `run` |
| 影响属性 | 逗号分隔 | `vocal` |
| 单次分钟 | 游戏内分钟 | `1` |

### 5.3 action_results（行为结果表）

一个行为在不同条件下可以有**多套**数值与文案。

| 列 | 含义 | 示例 |
| --- | --- | --- |
| 结果id | 唯一 ID | `res-vocal-tired` |
| 行为id | 属于哪个行为 | `vocal-karaoke` |
| 行为条件 | **表达式**，空=默认 | `stamina < 30` |
| 优先级 | 数字小的先匹配 | `1` |
| 体力 / 金钱 / 心情 / 饱腹 / 粉丝 | 增减量 | `-10` / `-50` / `-1` / `-6` |
| 演唱 / 舞蹈 / 演技 / 口才 | 增减，支持区间 | `1~3` |
| 行为文案 | 日志里显示的文字 | 你在包间里吼了两小时。 |

> 匹配规则：按优先级从低到高，取**第一个条件成立**的结果；都不成立用空条件那条。

## 6. 条件表达式（写在各「条件」列）

语法接近 Godot / SQL：

```text
dance >= 20
total >= 120
hasFlag("ev:debut")
stamina < 20 and money >= 500
fans.stage >= 100
trait.passion >= 3
mood < 40
neg.stress >= 60
```

| 类别 | 可写 |
| --- | --- |
| 逻辑 | `and` `or` `not`，也支持 `&&` `\|\|` `!` |
| 属性 | `vocal dance acting talk`（或 演唱/舞蹈/演技/口才） |
| 三轴 | `self others fit` |
| 状态 | `stamina mood satiety` |
| 聚合 | `total`（四项属性总和） |
| 粉丝 | `fans.stage` `fans.gachi` 等 |
| 固有 | `innate.height` / `innate.appearance` … |
| 性格 | `trait.ambitious` 等 |
| 负向 | `neg.stress` / `neg.fatigue` 等 |
| 熟练度 | `prof.song_prof` 等 |
| 标记 | `hasFlag("ev:debut")` |
| 函数 | `sum(...)` `max(...)` `min(...)` `abs(x)` |

> 单元格以 `{` 开头会按旧 JSON 格式解析；新内容请统一写表达式。

## 7. 校验与报错

`pnpm check:data` 会检查：

- JSON 能否解析、必填字段是否缺失
- 引用是否闭环：`actions.displayCondition`、`results.actionId`、`choices.eventId`、`tasks` 条件、`channels.poolId`、`pools.members`
- 枚举是否合法（分类、粉丝类型、结局分组…）
- `requires` 表达式能否编译：变量名必须在白名单里（裸字段 `ambitious` 等价于 `trait.ambitious`，规则与代码共用 `packages/core/src/expr-rules.js`）、比较号右边必须是数字

| 报错 | 原因 | 解决 |
| --- | --- | --- |
| `不是合法 JSON` | 条件列写坏了 | 改回表达式或补全 JSON |
| `找不到行为 xxx` | results 引用了不存在的 actionId | 检查 id 拼写 |
| `skip xxx.xlsx` | 文件被 Excel 占用 | 关闭 Excel 重跑 |
| 游戏里看不到改动 | 只改了 Excel 没导入 | `pnpm content:import` |
| `choices.json 校验失败：… 第 58 行 manager-doubt/firm: requires "amvitious >= 3" → 变量不存在（是否想写 "ambitious"？）` | requires 里变量名拼错 / 不是合法条件 | 按提示改 `content/all.xlsx` 对应行（行号是表里的物理行号），再 `pnpm content:import` |

## 8. 术语

| 词 | 含义 |
| --- | --- |
| 行动 / 时段 | 一天 3 个时段，每个时段做一件事 |
| 三轴 | 自我 / 他人 / 适配，隐藏，只用于结局判定 |
| 八层属性 | 固有 / 显性 / 状态 / 性格 / 负向 / 熟练度 / 三轴 / 粉丝 |
| 组合 | 主角 + NPC 的小队，上限 10 人（含主角） |
| 卡池 | 认识新朋友时的候选人名单 |
| 默契 | 重复遇到同一个人累积，影响抽中权重与占卜 |
| 标记 flag | 记录剧情进度，如 `ev:debut` |
| 结算 settle | 按行程把一段时间内所有行动一次性算完 |
