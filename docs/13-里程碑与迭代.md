## 0. 节奏原则

单人开发 + 业余时间，所以：

- 每个阶段都要**可玩**，而不是「做完一半不能跑」
- 优先跑通**最短闭环**，再堆内容
- 先把技术风险（时间推进、存档）打掉，再做内容

## 1. 阶段划分

### P0 · 可点击原型（技术验证）

**目标**：证明「排程 → 行动 → 数值变化 → 存档」这条链路能跑通。

| 交付 | 验收 |
| --- | --- |
| 页面骨架 + 纯文本状态区 | 本地 `pnpm dev` 能打开 |
| 假时钟 + 推进 1 天 | 单测通过 |
| 存档写入 / 读取 | 刷新页面进度还在 |
| 一次行动结算 | 日志出现数值变化 |

**不做**：文案打磨、事件、粉丝、赞助。

### P1 · MVP（最小可玩闭环）

**目标**：一个陌生人能完整玩 30 分钟不卡住。

| 交付 | 验收 |
| --- | --- |
| 训练 / 通告 / 休息 三类行动 | 都能结算并影响数值 |
| 经济闭环（赚钱 + 花钱） | 玩家能理解「钱怎么来」 |
| 存档槽 + 自动保存 | 关掉再开不丢 |
| 排程自动流逝 | 排好后时间自动跑，遇事件停 |
| 30 条以上行动文本 | 连续 5 次不重复 |

### P2 · 内容期（留存）

- 剧情事件 20+ 
- 粉丝与舆情
- 阶段推进与解锁
- 设置页（字号、深色、老板键）

### P2.5 · 联机期（核心粘性）

> 依据 [18 联机与异步结算](18-联机与异步结算.md)。**前置**：账号 + 后端 + 组合系统（演出人数由组合决定）。

- 账号与云存档（S14）
- 演出报名与撮合（S16）
- 异步演出结算（S17）
- 组合与阵容（S18）
- 文字战报
- 验收：报名 → 撮合（含 NPC 补位）→ 到点结算 → 战报与奖励

### P3 · 上线（对外）

- 部署 + 域名
- 赞助入口与感谢页
- 反馈渠道（Issue / 表单）
- 基础数据统计（可选，注意隐私）

## 3. 风险清单

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 文本产能不足 | 30 分钟后无内容 | 模板化 + 变量组合，先保证量 |
| 数值不好玩 | 循环没成就感 | P0 就做数值模拟脚本，跑 30 天 |
| 时间规则反复 | 返工 | 优先定稿（见 12） |
| 范围蔓延 | 永远上不了线 | 严格遵守 03 的 P0 边界 |
| 只有自己玩 | 无反馈 | P1 后找 3–5 个上班族试玩 |
