# 26 · 条件表达式

> 条件可以用**表达式**写（Godot / SQL 风格），也可以用**旧的 JSON 对象**写。
> 解析器基于开源库 [filtrex](https://github.com/cshaa/filtrex)（MIT，安全沙箱，不允许循环/递归）。

---

## 1. 怎么写

在配置表的「显示条件 / 领取条件 / 完成条件」等单元格里直接写一行：

```
演唱 >= 100 && 舞蹈 < 50 && 总属性 > 200
```

或者：

```
vocal >= 100 and dance < 50 and total > 200
```

两种运算符都能用：

| 逻辑 | 可写 |
| --- | --- |
| 与 | `and` / `&&` |
| 或 | `or` / `\|\|` |
| 非 | `not` / `!` |

## 2. 变量

| 变量 | 含义 |
| --- | --- |
| `vocal` / `dance` / `acting` / `talk` | 四项显性属性（也可写 演唱/舞蹈/演技/口才） |
| `self` / `others` / `fit` | 三轴（也可写 自我/他人/适配） |
| `stamina` | 体力 |
| `money` | 资金 |
| `friends` | 朋友圈人数 |
| `total` | 四项属性总和 |
| `fans.stage` 等 | 各类粉丝（`stage` `gachi` `music` `live` `growth` `power`） |

中文别名：演唱、舞蹈、演技、口才、自我、他人、适配、体力、资金、粉丝数、总属性。

## 3. 函数与运算

| 写法 | 含义 |
| --- | --- |
| `sum(vocal, dance)` | 求和 |
| `max(a, b, ...)` / `min(...)` / `abs(x)` | 内置函数 |
| `hasFlag("ev:debut")` | 是否有某个标记 |
| `+ - * / %` | 算术（`^` 是乘方，`mod` 是取模） |
| `== != < <= > >=` | 比较 |
| `( )` | 括号 |

## 4. 例子

```text
// 三项同时满足
vocal >= 100 and dance < 50 and total > 200

// 或：体力太低或钱太少
stamina < 20 or money < 500

// 演出相关：舞台粉够多、且已出道
fans.stage >= 100 and hasFlag("ev:debut")

// 算术
sum(vocal, dance, acting, talk) >= 240
```

## 5. 旧 JSON 写法（仍然可用）

```json
{ "statsAtLeast": { "vocal": 100 }, "statsBelow": { "dance": 50 }, "statsSumAtLeast": 201 }
```

判断规则：单元格以 `{` 开头 → 按 JSON 解析；否则 → 当表达式。

## 6. 错误处理

| 阶段 | 行为 |
| --- | --- |
| 导入表格 | 写错语法会直接报错并指出位置 |
| 运行时 | 表达式不会抛异常；求值失败按「不满足」处理 |
| 变量拼错 | 编译期报「未知变量 xxx」 |

## 7. 实现位置

| 文件 | 内容 |
| --- | --- |
| `packages/core/src/expr.ts` | 表达式编译、变量解析、旧 JSON 兼容 |
| `packages/core/src/events.ts` | 事件条件 |
| `packages/core/src/tasks.ts` | 任务条件 + 条件中文描述 |
| `packages/core/src/content.ts` | 行为显示条件 |

> 选择 filtrex 的原因：语法就是 `and/or/not` + 比较运算，最接近 Godot Expression；
> 编译成 JS 函数后执行很快；沙箱内无法访问外部对象，安全。
