## 0. 任务与边界（先读这一节）

**任务**：产出可用于 Live2D 绑定的「角色基础模板」视觉基准稿，以及 6 张表情差分。

**基础模板 = 冻结的东西**（下游不得改动）：

| 项 | 内容 |
|---|---|
| 底模 | `01_body`（皮肤＋脸＋躯干＋四肢＋裸腿＋脚）、`02_face` |
| 表情 | 6 个（默认／微困／抿嘴笑／惊讶／不悦／紧张） |
| 发型网格 | 齐肩短发 7 片、双马尾 9 片（右高左低） |
| 几何 | 2.5 头身、10 条锚点线（见规格 §4）、画布 2400×3600 |
| 参数 | 25 个模型参数、7 组物理（见规格 §2.2 / §2.4） |

**边界（必须写进派单，避免下游交错东西）**：

- AI agent 只能交**平面视觉稿**（PNG）。**PSD 分层、ArtMesh 切分、锚点对齐、参数绑定、Cubism 导出不在本单内**，需另起 B2 单由人工／切层 agent 完成。生成图是「视觉基准」，不是可绑定的模型文件。
- 本单**不含服装／发色／饰品的设计**（B1 单，随装备设计推进）。基础模板一律用**默认装扮**：双马尾 + 自然黑 + 素色练习服（含帆布鞋）+ 饰品全无。
- **不许把红格打歌服画进底模**。它是第一套正式服装的设计稿，属于 B1 的部件，不是底模。

## 1. 项目背景（3 行）

- 文字养成型《地下偶像》游戏，Web 桌面浏览器，办公场景；主角是玩家自建的「容器」，5 个模板共用同一形象。
- 主角以 Live2D 半身/全身 Q 版形象出现在人物页与主界面小窗，无交互，靠待机动作撑「活着」。
- 风格定位：2D 日系 Q 版赛璐璐、2.5 头身、中高饱和高明度的「可爱」，不做低饱和写实。

## 2. 风格锚点（逐字复制，禁止改写）

> 下游生成时，**整段复制进 prompt 的 A 段**，一个字都不改。凭记忆重写 = 风格漂移的头号原因。

```
【风格锚点 v2 — idol_hero_01】
画风：2D 日系 Q 版赛璐璐，平涂纯色块，2 档硬边阴影（固有色 / 暗部），无笔触、无渐变
视角：正脸平视、无透视、无仰俯；全身站姿，脚尖内八 8°
光照：无方向平光（绑定稿），阴影只做"固有色压一档"，不做环境光与投影方向
线宽：单一内线深灰紫 #4A3F4D 2px；不加白色外描边（白外光由导出／引擎阶段统一添加，不进任何素材图）

色彩倾向：中高饱和 + 高明度（L 70–95），暖色为主（珊瑚粉 / 奶油白 / 蜜桃肤），
          冷色仅薄荷青作小面积强调；同屏高饱和色块 ≤ 2 处
禁忌：不出尖角（下颌、发梢、鞋头一律圆角）；不用纯黑描边；不用体积光/光晕/粒子；
      不做上挑大眼与成排睫毛；不写实解剖；不出现偶像产业标识与真实品牌
```

**配套硬规则（同样不得改写）**

| # | 规则 |
|---|---|
| 1 | 同屏高饱和色块 ≤ 2 处；第三处降到中饱和 |
| 2 | 皮肤必须比服装亮：`#FFE0CE` L91 > 服装 L75 |
| 3 | 发色落在 L 35–60；**黑发豁免**：用 `#2A2530` 深灰紫黑表现，暗部不低于 L55 的规则不适用于黑发本体（否则黑发不存在） |
| 4 | 发梢撞色面积 ≤ 4% 画面，由发色装备承载（B0 用纯黑，无撞色） |
| 5 | 暗部不低于 L 55（Q 版压深即「脏」）；内线 `#4A3F4D`，不用纯黑 |
| 6 | 状态不能只靠颜色：体力低要配动作（低头 / 眨眼变慢 / 呆毛塌 15°） |

**色彩板**：主色 `#F58CA6` 珊瑚粉｜辅色 `#FFF6EA` 奶油白｜强调 `#6FD6C0` 薄荷青 + `#FFCE5C` 亮黄｜皮肤 `#FFE0CE`｜默认发色 自然黑 `#2A2530`｜背景 `#F2EFE9`｜内线 `#4A3F4D`。

**比例公式**（画之前必须落这 10 条，与规格 §4 锚点一致）：
眼宽 = 头宽 ×0.30｜眼距 = 眼宽 ×0.8｜瞳孔中心 = 头顶往下 58%｜嘴宽 = 眼宽 ×0.55、位于 82%｜躯干高 = 头高 ×0.55（无腰线）｜腿长 = 全高 30%｜小圆手直径 = 头宽 ×0.18（不画手指）｜脚尖内八 8°｜双肩不等高 1px｜呆毛根部 x = 头宽中线（头顶正中居中）、y = 200（画布 3600 高）｜呆毛卷曲尖端统一朝画面左侧。

# 1) 必做：先取背景实际主色（AI 生成的"纯色底"往往不是色值本身！）

# 2) 用【第 1 步读到的实际主色】抠图，不要想当然写 #00FF00
#    例：实测 v1 三视图主色为 #18C018，则：
python "$TOOLS" keyout source/char_idol_base_front_v1.png --color "#18C018" --tol 30 --out out/char_idol_base_front_v1.png

# 3) 合规校验（只扫 out/）；脚本产物另存，不要覆盖人工回执

**实测警告（v1 三视图）**：生成图写的是「纯绿 `#00FF00`」，`palette` 实际报出的是 `#18C018 / #18B818 / #20C018` 一串偏暗绿。用默认 `--color "#00FF00" --tol 40` 只抠掉 **19,179** 个像素，图基本没变透明；改用 `--color "#18C018" --tol 30` 后抠掉 **848,004** 个、自动裁到 1494×962、半透明边缘 **0**。

| 参数 | 去底像素 | 输出 | 结论 |
|---|---|---|---|
| `#00FF00` / tol 40（默认） | 19,179 | 1536×1024 | 失败，图仍是不透明 |
| `#00FF00` / tol 48 | 841,136 | 1536×1024（未裁边） | 可用但四周有残留 |
| **`#18C018` / tol 30** | **848,004** | **1494×962（自动裁边）** | **推荐** |

> `keyout` 会自动按 alpha 包围盒裁边，所以**不需要再跑 `trim`**；`trim` 只用于已带透明边但边缘还有空框的存量图。`check --json` 输出的是脚本自己的扁平清单（`sheet/check.json`），**不是** §6.4 的 `manifest.json` 回执；回执由 agent 按 §6.4 结构手写，两者都要交。

> `keyout` 默认容差 `--tol 40`；若抠不干净先调小 tol，不要调大（调大会吃掉角色暗部）。白外光若被画进图里，会在这一步留下半透明毛边，`check` 会报「边缘半透明像素」——这正是 B0-01 禁白外光的原因。
