# 01 · 产品定位与目标用户

> 状态：🟡 待填 ｜ 负责人：陈曦 ｜ 更新：2026-10-27
上游：README ｜ 关联：02 核心玩法 · 08 摸鱼场景

## 本文回答什么

- 这个游戏**为谁**做？他们为什么需要它？
- 它和同类（偶像养成、放置类、番茄钟工具）**不一样在哪**？
- 什么算成功？什么明确**不做**？

## 0. 已知前提（来自需求源头，不需重复论证）

- 纯文字、无美术表现；Web 版
- 目标人群：上班族，在办公场景里「摸鱼」时游玩
- 节奏慢、拟真偶像生活（原「与番茄钟结合」已废弃，见 16 D-009）
- 初期免费 + 玩家自主赞助

## 1. 一句话定位

【已定】想给上班族在不方便玩大型游戏的场景下，体验到一种慢节奏的角色养成游戏，和上班节奏贴合

## 2. 目标用户

### 2.1 用户画像

|画像|工作状态|单次可用时长|核心诉求|会流失的原因|
|---|---|---|---|---|
|摸鱼型||1–3 分钟|短平快的正反馈||
|通勤型||10–20 分钟|有内容可推进||
|睡前型||15–30 分钟|沉浸、陪伴感||
|空闲型|||||

### 2.2 需求推导（每条都要能推出一个设计约束）

- 因为 ________，所以**不能有美术**也不影响体验：在工作场合，大幅可识别的绘画可能会影响到玩家在工作过程中被辨别为在摸鱼，玩家希望兼容努力上班的人设。
- 因为 ________，所以必须**慢**：上班期间，玩家有受到干扰的场景很多，且没有办法大量的精力投入，为了配合玩家的投入周期，且玩家不关注的时候，不过于影响工作进度，因此要慢
- 因为 ________，所以**番茄钟**是关键差异点，而不是附加功能：很多上班族会有自律的心理需求，但是又不一定能够完全专注，需要休息，使用番茄钟的设定，将游戏的操作环节和番茄钟相结合，给到用户提高工作效率，又得到放松的体验。

> ⚠️ **2026-10-29 作废**：番茄钟设计已整体删除（见 [16 D-009](16-决策记录.md)）。原因是「提前规划 → 自动流逝」与「在场专注」互斥。
> 这段推导的前提（上班族需要自律工具）仍然成立，但落点要换。
- 因为上班族的碎片时间**不可预测、随时会被打断**，所以**不能要求整块专注**：25 分钟不被打断与工位场景冲突。改用「排程 → 自动流逝」，玩家排好计划就能走，回来直接看结果。差异点因此落在「**碎片时间原生的节奏** + 异步组团演出」，见 [18](18-联机与异步结算.md)。
- 因为 ________，所以**单次操作必须足够短**：玩家受干扰的场景过多，会有突发状况打断游戏操作/状态

## 3. 竞品与参照

|参照对象|学什么|不学什么|
|---|---|---|
|旅行青蛙|低频、留白、回来有惊喜|过度被动、玩家没有决策|
|偶像大师 / 偶像梦幻祭|属性成长与舞台反馈|重美术、重抽卡、重肝|
|放置类（Melvor Idle 等）|长时间轴成长|数值膨胀、无限堆叠|
|番茄钟 App（Forest 等）|专注本身即奖励|纯工具、无叙事粘性|

银河奶牛-学页面样式、数值 不学高频操作、过于复杂系统

喵国建造者-学页面样式、玩法  不学简单重复、缺少选择和判断

## 4. 反需求（明确不做）

- [x] 不做美术 / 立绘 / 音频（第一期）
- [x] 不做**实时**联机（第一期）
- [x] 不做体力付费墙（第一期）

> ⚠️ 原「不做联机/排行榜」已作废：**异步组团演出是中期核心玩法**，见 [18](18-联机与异步结算.md)。反需求只保留「实时联机」——它和摸鱼场景冲突。

> 反需求和技术债务一样重要：写下「不做什么」，才能在评审时拒绝需求蔓延。

## 5. 成功指标

|指标|目标（上线首月）|为什么看它|
|---|---|---|
|次日留存|60%|验证「明天还想回来」|
|单次会话时长|【待填】（摸鱼场景宜 1–5 分钟）|验证节奏是否贴合场景|
|单日决策次数 / 人|【待填】|验证「排程 + 自动流逝」是否被使用|
|赞助转化率|【待填】|验证免费模式能否自持|
|大演出参与率（联机上线后）|【待填】|验证异步联机是否真的成为留存钩子|
|周结算回访率|【待填】|周日回来领奖的人有多少|
