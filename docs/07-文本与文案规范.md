# 07 · 文本与文案规范

## 本文回答什么

- 所有文案用同一种语气、同一套格式？
- 代码里的文案 key 怎么命名、怎么插值？
- 什么能写、什么不能写？

## 0. 为什么纯文字项目更需要这份文档

没有美术兜底，**文字的错别字、称呼混乱、标点不一，就是画面崩坏**。这份文档是内容的质量底线。

## 1. 语气与人称

| 项目 | 约定 |
| --- | --- |
| 叙述人称 | 【待填】（例：第二人称「你」） |
| 偶像称谓 | 【待填】（例：直呼名字 / 艺名） |
| 玩家称谓 | 【待填】（例：「你」/「经纪人」） |
| 整体语气 | 【待填】（例：克制、平实、偶尔幽默） |
| 句子长度 | 单句 ≤ ___ 字，优先短句 |
| 标点 | 中文全角；省略号用 `……`；不用感叹号堆叠 |

## 2. 必守禁则

- [ ] 不写需要图像才能理解的描述
- [ ] 不出现真实艺人姓名、真实公司名
- [ ] 不写突破审核红线的内容（涉政、低俗、未成年相关）
- [ ] 不用网络烂梗（三个月后就看不懂）
- [ ] 不写玩家看不到的「作者视角」吐槽

## 3. 文案 key 命名

```
<域>.<对象>.<状态>

gig.audition.start
gig.audition.success
action.training.sing.desc
event.first_debut.text
ui.save.overwrite_confirm
```

规则：

- 全小写，下划线分词，点号分层
- 前缀必须是已有域（`ui` / `action` / `gig` / `event` / `fans` / `system`）
- 同一含义只用一个 key，不复用不同语境

## 4. 变量插值

统一用 `{{name}}` 语法，禁止在文案里拼代码字符串。

| 变量 | 含义 | 格式 |
| --- | --- | --- |
| `{{idolName}}` | 偶像名 | 原样 |
| `{{money}}` | 金额 | 千分位 + `¥` |
| `{{n}}` | 数值 | 需带符号时用 `{{signed n}}` |
| `{{time}}` | 游戏内时间 | `HH:mm` |

示例：

```
"{{idolName}}练了两个小时，声带有点紧。（+{{n}} 唱功）"
```

## 5. 排版约定

| 场景 | 规则 |
| --- | --- |
| 日志条目 | 一条一句，前缀 `> ` |
| 数值变化 | 用 `+2 唱功` / `-10 体力`，数字与单位间空格 |
| 时间 | 游戏内 `Day 3 · 14:20` |
| 金额 | `¥3,200`，超过一万用 `¥1.2 万` |
| 强调 | 用 `【】` 包裹系统词，不用粗体 |
| 空行 | 段落间一个空行，不连空两行 |

## 6. 文本与数值分离

- 文案只存在 `src/content/text/*.json`，不硬编码在组件里
- 需要随数值变化的文案，用模板 + 变量，不写 if/else 拼句子
- 每条文案标明「是否可重复」（防止「第一次」类文案重复出现）

## 7. 校验清单（可自动化）

- [ ] 所有 key 在 zh-CN 中都有值
- [ ] 没有残留 `{{}}` 未替换变量
- [ ] 标点检查（英文标点混入）
- [ ] 单条文案长度超阈值告警
