# 24 · 组合与社交系统

> 设计草案见 [19 组合与招募](19-组合与招募.md)；本文是**当前实现与规则**。
> 记录组合、朋友圈、认识的规则。改数值看 `data/channels.json` 与 `data/balance.json`，
> 改逻辑看 `packages/core/src/friends.ts` 与 `members.ts`。

---

## 1. 组合规则

| 规则 | 说明 |
| --- | --- |
| 人数范围 | **1 ~ 10 人**（含主角） |
| 主角 | **每个组合都默认包含「自己」**，可以同时在多个组合里 |
| NPC | **只能属于一个组合**，邀请时会检查其它组合 |
| 创建条件 | 必须先出道（四项属性之和 ≥ 出道门槛） |
| 主角卡片 | 每个组合的第一张，固定显示「我 / 主角 / 队长」 |
| 管理 | 组合头部「管理」进入管理模式：卡片右上角 ✕ 可移出成员 |

> 人数上限来自 `balance.json` 的 `partyMax`（默认 10）。主角占 1 个位置，
> 所以每个组合最多再邀请 9 个 NPC。

---

## 2. 朋友圈

认识的人先进入**朋友圈**，再邀请进组合。

```
认识新朋友（花钱） → 朋友圈 → 邀请 → 组合
```

| 概念 | 说明 |
| --- | --- |
| 来源渠道 | `data/channels.json` 配置，每个渠道花费不同、人群偏向不同 |
| 资质 | 0.8 ~ 1.15 的系数，越高入队后属性越强 |
| 偏向 | 唱功 / 舞蹈 / 演技 / 口才 / 均衡 |
| 上限 | 朋友圈本身不设上限（花钱就能认识，但钱有限） |

### 抽取规则

1. 每个渠道从**自己的卡池**里抽人（`pools.json`，`channels.poolId` 关联）
2. 先判定**抽空**：10% 概率没遇到合适的人（**钱照扣**）
3. 没抽空时按卡池抽人：
   - 池子里还有没认识过的人 → 只在**新人**里等概率抽
   - 全都认识过了 → 全池加权抽，**满默契的人权重减半**
4. 抽到已认识的人 → 该角色**默契 +1%**（上限 10%）

### 当前渠道

| 渠道 | 花费 | 偏向 | 资质区间 |
| --- | --- | --- | --- |
| 逛漫展 | ¥200 | 舞蹈 / 演技 | 0.80 ~ 1.05 |
| 看演出 | ¥300 | 演唱 / 舞蹈 | 0.85 ~ 1.10 |
| 朋友介绍 | ¥500 | 全属性 | 0.95 ~ 1.15 |

## 3. 邀请规则

| 情况 | 结果 |
| --- | --- |
| 没有组合 | 不能邀请，提示先创建组合 |
| 组合已满（已有 9 个 NPC） | 不能邀请，提示「组合满了（最多 10 人）」 |
| 该 NPC 已在别的组合 | 不能邀请，提示「这个人已经在别的组合里了」 |
| 正常 | 从朋友圈移除，加入当前组合，写日志 |

## 4. 交互约定

| 操作 | 行为 |
| --- | --- |
| 点击成员卡片 | **翻转**查看该成员属性；可**同时翻转多张**方便对比 |
| 管理模式下点击卡片 | 不翻转，只显示 ✕ 按钮（防误触） |
| 切换组合 | 组合名后面的小标签，主角卡跟着切换 |
| 配置按钮 | 占位（改组合名等尚未实现） |

---

## 5. 与其他系统的关系

- **出道**：出道后才能创建组合，出道门槛在 `balance.json`
- **演出**：演出收益按组合整体属性计算（后续扩展）
- **数值**：NPC 属性 = 主角当前属性 × 资质，再按倾向加权
